### 0.2 为什么重构

1. **用逐行的源码编辑器去模拟 Typora 的树形文档。** CodeMirror 6 的每一行是一个 `div.cm-line`，表达不了嵌套、外边距折叠、有序编号和表格布局，只能在 JS 里重新算：块间距和折叠约 520 行（`ContinuousMarkdownEditor.vue:1228-1750`）、列表符号和编号约 340 行（`:1781-2117`）、点击和拖选换算回源码位置约 2,000 行、表格在 Widget 里另起一个 Vue 应用和单元格编辑器约 5,100 行。指针换算的回归测试有 12 个文件，间距和块边界的有十来个。
2. **一份文档几套解析**，块边界要靠互相对齐，对不齐就是回归。
3. **每次按键、每次移动光标都做全文计算**：装饰依赖 `selection`，每次都对全文 `split("\n")` 重建；内容一变还要另做一次非增量的完整解析；每次按键把全文发给 `App.vue`，同步重算大纲、统计、查找，再把全文写进 localStorage。
4. **职责堆在几个巨型文件里**，依赖方向混乱（`markdownLinks` 依赖编辑器的 `editorBlocks`，`editorCommands` 依赖渲染层 `markdown`），编辑器组件直接依赖 Tauri。
5. **安全边界缺失**：CSP 为 `null`；资源协议范围是 `["**"]`；`read_text_file`、`write_text_file`、`trash_path` 接受任意路径；Mermaid 设成 `securityLevel: "loose"`，SVG 直接写进 `innerHTML`；发布版开着开发者工具。
6. **桌面行为不全**：只有一个窗口；不监听外部修改；PDF 导出要装 LaTeX；拼写检查看不到建议；主题写死两套；界面只有中文；`main.rs` 没有处理 macOS 的 `RunEvent::Opened`（从访达打开文件走的是这个事件）。
7. **测试锁死源码文本**：至少 29 个测试文件读取 `.vue`、`.css` 源码，用正则断言 CSS 规则和代码原文，拆文件、改名就成片失败。

### 0.3 目标

- 功能对齐 Typora（第 2 章）；Marko 已有、Typora 没有的（如图表大图查看器 D-5）保留。
- 打开、不改、保存逐字节不变；改一处只影响那一块（E-1）。
- 编辑区、导出、打印用同一份主题 CSS 和同一条渲染管线，所见即所得。
- 打开任何来路不明的 Markdown 文件都不会执行脚本、越权读写文件（X-1）。
- 支持 Windows x64、macOS Apple Silicon、Linux x64（R 章）。

### 0.4 已定的事（2026-11-23）

1. 桌面壳从 Tauri 2 换成 Electron。
2. 编辑器内核换成 ProseMirror 的树形文档（通过 Tiptap 使用，见第 14 条），DOM 结构和 Typora 一致；Lezer 是唯一的结构解析器；代码块、公式块、HTML 块、Front Matter 和整篇的源码模式用 CodeMirror 6。
3. 文本块里保留行内 Markdown 原文，语法标记用装饰隐藏，光标进入时显示（1.5、1.6 节）。
4. 无损序列化：没改过的块原样输出原始源码片段（1.5 节）。
5. 应用外壳用 Vue 3；编辑器内核不依赖任何框架。
6. 不考虑工程量，只按合理性定方案。
7. 现有测试里「文本 + 选区 → 文本 + 选区」形式的期望，迁移成新架构的行为规格；读取源码文本做断言的测试不迁移。
8. 支持 Linux x64（R-3）。
9. macOS 跟着最新的 Electron 走：系统版本下限按所用 Electron 版本的要求，不为旧系统单独兼容；安装包只出 Apple Silicon，同现在（R-2）。
10. 不导入旧版本（Tauri）的设置、最近文件和未保存的草稿：它们存在 WebView2 / WKWebView 的 localStorage 里，Electron 读不到。2.0.0 的发布说明提醒用户升级前先保存所有文档。
11. Typora 社区主题看难易：阶段 3 用几个常用的 Typora 主题试一遍，只需对齐类名、补少量兼容样式就顺手支持，改动大就不做（A-3）。
12. 编辑器库对外的引用方式、导出的类型、组件的属性、事件和方法都保持不变（K-1）。
13. 中文是默认界面语言，界面文字从一开始都经过 i18n；English 翻译不作为发布条件，改动大就先不做（L-2）。
14. 能用成熟的开源库就用，不自己实现；每一项用什么见 1.0 节。界面组件用 Element Plus；编辑器在 ProseMirror 之上用 Tiptap（MIT）。只有两类自己写：无损的文档模型（1.5 节），没有现成的库；自动配对、占位这类只有几十行、又没有合适库的小插件。

## 4 重构计划〔已做〕

2026-11-23 定的目标：换掉桌面壳和编辑器内核，功能对齐 Typora（第 2 章）。

### 4.1 做法

- 一个阶段一个阶段做。每个阶段开始前，把本文件里涉及的部分给用户看，同意后再写代码；做完跑 `npm run check`、`npm test`，按第 2 章的编号逐条核对，汇报后再进下一阶段。
- 新代码放在 `packages/`、`apps/`、`test/`，和旧代码（`src/`、`src-tauri/`、`tests/`、`component-tests/`）并存。旧应用照常能构建、发布；重构期间旧代码只修严重问题，不加功能。阶段 7 切换后删掉旧代码。
- 不新建分支，直接在本地工作区修改；什么时候提交由用户决定（2026-11-23 定）。
- 发现本文件做不到、对不上时停下来，说明问题和建议的改法，用户确认后先改本文件，再继续写代码。
- 〔新增〕的功能放在它所属的阶段里做，不单独排期。

### 4.3 行为规格的格式

`test/behavior/` 下每个功能分类一个文件（如 `E.md`），每条规格一个小节：标题写编号和要验证的事，`before`、`after` 两个代码块写操作前后的 Markdown，中间一行写操作。`‸` 表示光标，`⟦`、`⟧` 表示选区的两端。

````
### E-5 空的列表项上回车，变成正文

```before
- 第一项
- ‸
```

操作：`Enter`

```after
- 第一项

‸
```
````

- 操作写按键（`Enter`、`Shift+Tab`、`Ctrl+B`）、输入的文字（`输入 "# "`）或命令名（`命令 toggleTask`）。
- 测试把 `before` 解析成文档、按操作执行、序列化后和 `after` 逐字节比较，光标和选区也要对上。
- 阶段 0 从现有测试里导出；之后新增、修改的行为先在这里加一条。
- 细则（回车符、反向选区、旧代码的重放注释、设置写在哪）见 `test/behavior/README.md`。
