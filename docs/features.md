# 功能清单

本文件是 Marko 功能的**唯一依据**：每个功能一个编号（如 `E-3`），要点就是验收标准。架构、每个功能落在哪些模块见 [architecture.md](architecture.md)。

使用规则：

1. 新增、修改、删除功能，**先改本文件**（再在 architecture.md 第 3 章落位到模块），然后才改代码。代码和本文件不一致时，以本文件为准：要么改代码，要么先改本文件。
2. 每个功能一个编号，编号不复用；删掉的功能移到本章末尾「已删除」，写明原因。
3. 每条要点都是**验收标准**：修改后逐条核对。
4. 条目没写到的交互细节，以 `test/behavior/` 的行为规格和 Typora 1.14.15 的默认行为为准；两者冲突时，在条目里写明取哪个。
5. 标〔待确认〕的是还要用户定的地方。
6. 文中的 `Ctrl` 在 macOS 上是 `Cmd`，`Alt` 是 `Option`。
7. 章节号沿用拆开前的重构计划.md：本文件是第 2 章；文中的「1.x 节」「第 3 章」在 architecture.md，「0.x 节」「4.x 节」在重构计划.md。

## 2 功能清单

### 2.0 术语

| 术语 | 含义 |
|---|---|
| 文档 | 一个 Markdown 文件，或还没保存的新文档 |
| 块 | 段落、标题、引用、列表、表格、代码块等块级元素 |
| 文本块 | 直接装文字的块：段落、标题、表格单元格、定义列表的词条 |
| 行内原文 | 文本块里存的这一块行内内容的 Markdown 原文，含 `**`、`` ` ``、`[]()` 等标记 |
| 片段 | 行内原文里的一个语法单元：粗体、链接、行内公式等 |
| 展开 / 收起 | 片段显示出 Markdown 标记 / 只显示排版结果 |
| 原子片段 | 收起时用渲染结果代替显示的片段：行内公式、emoji、脚注引用、行内 HTML、图片、HTML 实体 |
| 写法 | 同一种语法的不同写法，如列表符号用 `-` 还是 `*`、强调用 `*` 还是 `_`、围栏用几个反引号 |
| 工作区 | 侧栏里打开的文件夹 |
| 源码模式 | 整篇以 Markdown 源码编辑的模式 |

### 2.1 通用规则

有几条规则管着很多功能，在这里各写一次，各条目只引用（写作「通用规则 N」）。

1. **无损**（E-1）：打开、不改、保存逐字节不变；改一处只影响那一块，沿用这一块原来的写法。
2. **所见即所得**（A 章、O 章）：编辑区、导出、打印、复制为 HTML 用同一份主题 CSS 和同一条渲染管线。
3. **显示就是含义**：编辑后，块的结构总是和这份 Markdown 重新解析的结果一致（1.5.5）。
4. **撤销**（E-6）：所有修改都能撤销，包括自动转换、表格操作、图片插入、代码块和公式块里的修改、源码模式里的修改。
5. **一个窗口一个文档**（F-1～F-3）：同一个文件只在一个窗口里打开；设置改动所有窗口同时生效。
6. **菜单**：每个命令都在原生菜单里，显示快捷键；编辑区、侧栏的右键菜单也是原生菜单（W-6、L-1）。
7. **不可信内容**（X-1）：文档里的 HTML、图表、链接都按不可信内容处理。
8. **界面文字**（L-2）：菜单、对话框、提示、设置的文字都可以翻译，代码里不写死某一种语言。
9. **输入法**（E-12）：输入法组合期间不做任何自动处理，上屏后再处理。

### 2.2 编辑核心（E）

#### E-1 无损读写

- 打开后不做任何修改就保存，文件逐字节不变：换行符、空行、缩进、列表符号、强调字符、围栏、表格的竖线和空格、HTML、实体都不变。
- 改了某一块，其他块逐字节不变；改过的块沿用原来的写法（列表符号、序号分隔符、强调字符、围栏字符和长度、缩进宽度），这一块里没改的字符也不变。
- 换行符沿用文件原来的；改过的块用文件里出现最多的那种；新文档用 S-3 的「默认换行符」。S-3「保存时插入末尾换行」打开时，保存时末尾补一个换行。
- 带 BOM 的文件保存时保留 BOM；编码见 F-18。BOM 不是能编辑的内容：编辑器里命令、源码模式看到的源码都不带它（第一行从内容开始），保存（`getMarkdown`）时按 `doc` 上记的写回；对外的偏移（打开时给的光标位置、读出来的选区）按带 BOM 的原文算。

#### E-2 行内语法的显示与编辑

- 光标在一个片段里面，或紧挨着它的边界时，这个片段展开，显示它的标记（`**`、`*`、`~~`、`` ` ``、`[文字](地址)`、`$`），可以直接改标记；光标离开就收起，只显示排版结果。
- 片段嵌套时（如粗体里的链接），光标所在的每一层都展开。
- 原子片段收起时显示渲染结果（公式、emoji、脚注序号、过滤后的 HTML、图片、实体对应的字符）；展开时显示原文，行内公式和图片在原文旁边显示预览。
- 单击、拖选收起的文字时，光标落在点到的那个字符上。
- 链接收起时，单击只放光标，Ctrl+单击打开（N-4）。

#### E-3 块级标记

- 标题的 `#`、列表符号、任务框、引用的 `>`、代码块的围栏不出现在文字里，由块本身呈现：标题字号、列表圆点和序号、复选框、引用左边的竖线。
- 改块的类型用菜单、快捷键（B 章各条）或自动转换（E-4）。
- 文本块开头按退格：标题变正文；列表项变正文，再按一次并入上一块；引用、Callout 里的第一段移出来。
- 光标、选区进不了这些标记和行首的缩进：落在标记上时到内容开头；选中整行、整块就是从内容开头选起；命令的结果落在标记里时（如去掉代码块的围栏后剩下的 `> 文字` 是引用）光标到内容上。选中分隔线、目录是选中这一块（节点选区）。

#### E-4 自动转换

- 在正文段落开头输入下面的内容，段落马上变成对应的块（通用规则 9）：

  | 输入 | 变成 |
  |---|---|
  | `# `～`###### ` | 一到六级标题 |
  | `> ` | 引用 |
  | `- `、`* `、`+ ` | 无序列表 |
  | `1. `、`1) `（任意起始数字） | 有序列表 |
  | `- [ ] `、`- [x] ` | 任务列表 |
  | `> [!NOTE]` 等五种 + 回车 | Callout（B-13） |
  | ```` ``` ```` 或 `~~~`，后面可以跟语言，+ 回车 | 代码块（B-6）；没写语言时按 S-7 的默认语言 |
  | ```` ```mermaid ````、```` ```flow ````、```` ```sequence ```` + 回车 | 图表（D-3、D-4） |
  | `$$` + 回车 | 公式块 |
  | `---`、`***`、`___` + 回车 | 分隔线 |
  | `\| 列 \| 列 \|` + 回车 | 表格（T-1） |
  | `[TOC]` + 回车 | 目录 |
  | 文档第一行的 `---` + 回车 | YAML Front Matter |
  | `[^id]: ` | 脚注定义 |

- 段落的下一行（软换行后）输入 `===` 或 `---`，段落按 Markdown 的规则变成 Setext 标题（通用规则 3）。
- 转换后马上按 Ctrl+Z，撤回转换，留下输入的字符。
- 等回车（或空格）的写法（`packages/editor/src/plugins/defer.ts`）：光标在这一行末尾、还在输入时，段落里先照样是输入的字符，按回车（表里写了「+ 回车」的）或接着输入空格才转换：
  - 分隔线 `---`、`***`、`___`（也是文档开头的 Front Matter），围栏 ```` ``` ````、`~~~`（后面可以跟语言），`$$`、`\[`，`[TOC]`，引用里的 `[!NOTE]`；
  - 还没输入空格的 `#`～`######`、`-`、`*`、`+`、`1.`、`1)`、`>`：输入 `- ` 才变成列表项，不会在输入 `-` 时先变成空列表项；
  - 段落第二行起的 `==`、`--`（两个字符以上）：输入完、光标离开这一行或按回车才变成 Setext 标题，免得在输入 `---` 的中途先变成标题；
  - 像分隔线的一行（如空段落里按 Ctrl+B 得到的 `****`）：光标在这一行任何位置都不转换。连同外面容器的标记一起看（嵌套列表 `* * ` 里再输入 `* `，最里面一层是空的，整行 `* * * ` 却是分隔线）；
  - 光标后面只剩自动配对补出来的右半边（`[!NOTE` 后面的 `]`）时也算在行尾。

#### E-5 回车、退格与 Tab

- 回车：
  - 正文、标题里拆成两块；标题末尾回车，下面新开一个正文段落；
  - 列表项里新建同级的项（任务列表的新项不勾选）；空的列表项上回车，项向外缩一级，最外层时变成正文；
  - 引用、Callout 里拆段后还在里面；空段落上回车退出引用。
  - 空列表项退出后留下的空行（不属于任何块）上有光标：编辑器在那里放一个空段落，还空着时序列化出来正好是那一行，输入了内容就是一个新段落、前后的空行按规则补（`Origin.placeholder`）。
  - 按 CommonMark 解析（`test/behavior/README.md`）：缩进不够进不了上一项、又不能另起列表项的 `    1. ` 是段落的续行，不是空列表项；没有结尾的 `$$` 下面是普通段落，Shift+回车是段落里的换行；10 位以上的序号不是有序列表，回车不续写序号。
- Shift+回车：段落里换行（软换行）。软换行的显示按 S-6「保留单个换行」。
  - 〔待确认〕编辑区里软换行总是显示成换行（ProseMirror 要求可编辑区 `white-space: pre-wrap`，换行没法显示成空格又能正常编辑）；S-6 这一项只影响导出、打印（@marko/render）。
- 退格：见 E-3；自动配对的符号中间按退格，两个一起删（E-9）。
- Tab、Shift+Tab：列表项缩进、反缩进（宽度按 S-5「Markdown 缩进宽度」）；表格里到下一个、上一个单元格（T-2）；代码块里按「代码缩进宽度」缩进（B-6）；其他位置按 S-5「Shift+Tab 自动缩进」。

#### E-6 撤销与重做

- Ctrl+Z 撤销；Ctrl+Y 或 Ctrl+Shift+Z 重做。
- 整篇共用一条历史（通用规则 4）；代码块、公式块里的 CodeMirror 编辑也进同一条历史。
- 连续输入合并成一步；停顿 3 秒以上另起一步。
- 切换源码模式不清空历史（E-11）。
- 撤销回到改之前的原文、重做回到改之后的原文，逐字节不变（块前空行、文末空行都算；1.5.4）。

#### E-7 选择

- Ctrl+A 全选整篇；光标在代码块、公式块里时，第一次只选这一块的内容，再按一次选整篇。全选以后删除、剪切、粘贴、输入换掉的是整篇原文，连同开头、结尾的分隔线、目录；从块外选到表格最后一格、代码最后一行的末尾（或从第一格、第一行的开头选到块外）时，删掉的连同这个块的标记，不留行尾的 ` |`、结尾的围栏。
- 「编辑 → 选择」：当前词 Ctrl+D、样式范围 Ctrl+E（I-7）、当前句子、当前行 Ctrl+L、当前段落。
- 双击选词，三击选整个文本块。
- 可以跨块拖选；选区里的代码块、公式块、表格整块选中。

#### E-8 删除与移动

- 「编辑 → 删除」：当前词 Ctrl+Shift+D、当前句子、样式范围、当前段落。
- 「编辑 → 行操作」：复制当前行、删除当前行 Ctrl+Shift+Backspace、上移 Alt+↑、下移 Alt+↓。在排版视图里，「行」指光标所在的块：列表项按项、表格按行（T-3），其他按整块；源码模式里按行。

#### E-9 自动配对

- S-5「自动配对」打开时，输入左半边自动补右半边：`(`、`[`、`{`、`"`、`'`、`` ` ``、`$`，以及中文的 `（`、`【`、`《`、`「`、`『`、`“`、`‘`。
- 有选区时输入上面的符号，或 `*`、`_`、`~`，把选区包起来。
- 光标后面正好是要输入的右半边时，直接跳过它；光标在一对符号中间按退格，两个一起删。
- 在空段落开头快速输入 `$abc`，偶尔成了 `abc$`：不是自动配对的问题（`$` 没有选区时不配对），是 Chromium 在只有占位 `<br>` 的空段落里插字时，偶尔把字插在 `<br>` 前面、光标留在原地，ProseMirror 按 DOM 里的选区把光标放在了刚插的字前面。改法（`plugins/textInput.ts`，优先级最低的输入处理）：在光标处插入、读回来的选区还停在插入点上时，把光标放到插入的字后面（打字不会出现这种选区）。端到端测试连续输入 12 轮验证。

#### E-10 智能标点

- S-6「智能引号」「智能破折号与省略号」打开时，只改显示：直引号显示成弯引号，`--`、`---` 显示成破折号，`...` 显示成省略号；文件里还是原来的字符（通用规则 1）。
- 代码、公式、网址、HTML 里不处理。

#### E-11 源码模式

- Ctrl+/ 切换；整篇用 CodeMirror 6 编辑 Markdown 源码，带 Markdown 语法高亮，代码块里的代码按语言高亮。
- 切换时光标、选区和滚动位置按源码偏移保留（1.5.6）。
- 源码模式下查找、替换、大纲、字数统计照常。
- 撤销历史跨模式连续（E-6）。
- CodeMirror 里写的就是文档的原文，不被「规范化」改写：每次改动按块重新解析，结果和写的对不上（或出错）时整篇重新解析，以写的为准。

#### E-12 输入法

- 输入法组合期间：片段不展开也不收起，不做自动转换、自动配对、emoji 补全、不变式的重新解析；上屏后按上屏的文字处理。
- 任何文本块里都能组合输入（含表格单元格、标题、列表项、引用、Callout），候选框跟着光标。

### 2.3 块（B）

#### B-1 段落与换行

- Ctrl+0 把当前块变成正文段落。
- 软换行（E-5）、硬换行（行尾两个空格或 `\`）按 Markdown 显示，源码保持原样。

#### B-2 标题

- 一到六级：Ctrl+1～Ctrl+6；Ctrl+= 提升、Ctrl+- 降低一级。
- ATX（`#`）和 Setext（下划线 `===`、`---`）都支持，改级别时沿用写法；Setext 只有一、二级，改到三级以下时换成 ATX。
- 每个标题有锚点 id，规则和 Typora 一致，文档内链接 `[x](#标题)` 在两边都能跳；目录、大纲、导出的 HTML 用同一个 id。
- 锚点规则照 Typora 1.14.15 的源码（`titleToAnchor`、`fetchAnchorList`）：标题显示出来的文字转小写、去两头空白；每个空白和连字符各变成一个 `-`（不合并），长破折号算三个、短破折号算两个；去掉所有 Unicode 标点和 `+`、`=`（下划线、中文标点也去掉；`$`、`^`、`` ` ``、`|`、`~`、`<`、`>` 和 emoji 保留）；和前面的锚点（含文档里的 `<a name>`）重名时第 n 个加 `-n`（从 `-2` 开始）；叫 `write` 的改成 `write-1`；没有文字的标题没有 id。

#### B-3 引用

- Ctrl+Shift+Q 把当前块放进引用，或移出引用；可以嵌套；里面可以放任何块。
- 懒惰续行（下一行没写 `>`）按 Markdown 规则属于这个引用；没改过的行保存时不补 `>`（通用规则 1）。

#### B-4 列表

- 无序 Ctrl+Shift+]、有序 Ctrl+Shift+[；缩进 Ctrl+] 或 Tab，反缩进 Ctrl+[ 或 Shift+Tab。
- 有序列表显示的序号按 Markdown：从第一项的数字开始，依次加一。插入、删除、移动项之后，后面各项源码里的数字改成连续的，分隔符（`.` 或 `)`）沿用。
- 紧凑列表和松散列表（项之间有空行）按原样显示和保存。
- 有序列表的项也可以是任务（`1. [ ] `）。

#### B-5 任务列表

- Ctrl+Shift+X 把当前块变成任务列表；点复选框切换 `[ ]` 和 `[x]`；「段落 → 切换任务状态」切换光标所在的项。
- 勾选只改方括号里的那一个字符。

#### B-6 代码块

- Ctrl+Shift+K 插入；```` ``` ````、`~~~` 围栏和缩进代码块都显示为代码块，保存时保持原写法。
- 代码块总是一个 CodeMirror 编辑器，按语言高亮；高亮用 Lezer，和导出、打印的一致（通用规则 2）。
- 语言：代码块右上角显示语言，点开可以搜索、选最近用过的；改语言只改围栏后面的信息串。
- 默认语言（S-7）：不指定 / 最近使用 / 固定语言；「应用时机」决定通过 Markdown 输入（E-4）、通过菜单插入时是否套用。
- 显示行号、长代码自动换行按 S-7；Tab 按「代码缩进宽度」。
- 右键菜单：复制代码块内容、为选中内容调整缩进、为整个代码块调整缩进。
- 在最后一行按 ↓、第一行按 ↑ 离开代码块；文档以代码块结尾时，在最后一行按 ↓ 在后面新建正文段落。

#### B-7 公式块

- Ctrl+Shift+M 插入 `$$` 公式块（S-8「公式」打开时）。
- 写法：`$$`、带标签的 `$$ {标签}`、`\[…\]`；要有结尾围栏才算，结尾可以在很后面（Typora 1.14.15 实测）。GitLab 的 ```` ```math ```` 围栏是信息串为 math 的代码块，渲染成公式。
- 不在编辑时显示渲染结果；光标进入时显示源码编辑器（CodeMirror，LaTeX 高亮），下面实时预览。
- 渲染见 D-1，编号见 D-2，出错见 D-6。

#### B-8 分隔线

- 「段落 → 分割线」插入 `---`；`***`、`___` 等写法保持原样。

#### B-9 YAML Front Matter

- 只能在文档开头；「段落 → YAML Front Matter」插入，或在文档第一行输入 `---` 回车（E-4）。
- 显示为 YAML 编辑器（CodeMirror，YAML 高亮）；不属于正文，不导出成正文内容。
- `typora-root-url` 键决定图片相对路径的根目录（M-1）。

#### B-10 目录 [TOC]

- 单独一段 `[TOC]` 显示为按标题生成的目录，随标题实时更新；点条目跳到标题。
- 「段落 → 目录 [TOC]」插入；导出时一起输出。

#### B-11 脚注

- 引用 `[^id]` 显示为上标序号，按在文中第一次出现的顺序编号；鼠标移上去显示脚注内容；点击跳到定义。（Typora 1.14.15 的编辑区里上标显示标签，导出时显示序号——它的导出代码是 `<sup class='md-footnote'><a href='#dfref-footnote-1' name='ref-footnote-1'>1</a></sup>`；我们编辑区和导出都显示序号，导出的结构和 id 同 Typora：同一脚注第二处起的引用是 `ref-footnote-1-1`、`-2`……）
- 标签不分大小写，可以有空格和中文；定义可以在引用、列表里；续行缩进 4 格或懒惰续行；定义能打断段落，连着写的几条各是各的（Typora 实测）。〔和 Typora 不同〕Typora 的定义只有一行，下一行缩进 4 格时成了缩进代码块；我们的写法同 markdown-it-footnote、GitHub：续行属于脚注。
- 定义 `[^id]: 内容` 在原位置显示，带回到引用处的链接，多处引用时每处一个。
- 引用了但没有定义的，点击时在文末新建定义。
- 「段落 → 脚注」在光标处插入引用，并在文末新建对应的定义。
- 鼠标停在引用上显示脚注的内容（定义的原文，太长的截断到 300 字）：编辑器把它放在上标的 `data-tip` 上，组件用 Element Plus 的提示框显示（不用浏览器的 title，免得出两个）。

#### B-12 HTML 块与注释

- HTML 块不在编辑时显示过滤后的渲染结果（X-1）；光标进入时显示源码（CodeMirror，HTML 高亮）。
- `<video>`、`<audio>`、`<details>`、`<img>` 等照常显示；`<iframe>` 只显示 `https:` 地址的，并放进沙箱（1.10 节）。
- 「格式 → 注释」Ctrl+Shift+/ 把选中的内容包成 `<!-- -->`；注释在编辑区以灰色显示原文，导出时不输出。

#### B-13 Callout

- `> [!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` 显示为带图标和标题的提示框；「段落 → Callout / Alert」插入五种之一。图标同 GitHub、Typora，是 Octicons 里的；导出时标题（图标 + 名称）放在第一段开头，换行后接正文，同 Typora 的导出。
- 光标进入标题行时显示 `[!NOTE]` 原文，可以改种类；框里可以放任何块。
- `[!NOTE]` 在节点的属性上，不在文字里，标题是装饰（第一段开头的图标 + 名称，DOM 同导出）；改种类用命令 `callout(kind)`（光标在 Callout 里时只换种类）。
- 单击标题弹出种类选择（Element Plus 的下拉菜单，挂在标题上；图标同标题），选了别的种类就换，选现在的种类不动（命令遇到同一种会去掉 Callout）。

#### B-14 定义列表

- 词条下一行写 `: 说明`，显示为定义列表；「段落 → 定义列表」插入。
- 写法：一个词条可以有几条说明；说明后面紧跟「词条 + `: `」开始新的一组；说明的续行缩进 2 格以上，空行后缩进 4 格的接着属于它（多段）；词条和 `: ` 之间不能有空行；说明后面不缩进、又不是词条的行另起一段。
- 在词条和说明之间可以用方向键移动。

#### B-15 链接引用定义

- `[id]: 地址 "标题"` 不在编辑时显示为一行紧凑的引用定义，光标进入时显示原文；文中的 `[文字][id]`、`[id]` 按它解析。
- 「段落 → 链接引用」插入一条定义。

#### B-16 缩写

- 定义 `*[HTML]: Hyper Text Markup Language` 不在编辑时隐藏；文中出现的 `HTML` 加虚线下划线，鼠标移上去显示全称。
- 〔待确认〕定义在编辑区里一直显示（灰色、等宽，同链接引用定义），不加「显示 / 隐藏定义」的开关：ProseMirror 里藏起来的块点不到、方向键也进不去。
- 全称同脚注用组件的提示框显示（`data-tip`，虚线下划线）。

#### B-17 插入段落

- 「段落 → 在上方插入段落」「在下方插入段落」：在当前块的前面、后面新建一个空的正文段落；光标在列表、引用、表格里时，以最外层的块为准。

### 2.4 行内（I）

#### I-1 强调与行内代码

- 加粗 Ctrl+B、斜体 Ctrl+I、下划线 Ctrl+U（`<u>`）、删除线 Alt+Shift+5、行内代码 Ctrl+Shift+`。
- 有选区时把选区包起来，再按一次去掉；没有选区时插入一对标记，光标放在中间；光标在已有的这种样式里时去掉它。
- 新加的用 `**`、`*`、`~~`；已有的写法保持（通用规则 1）。
- 中日韩文字旁边的 `*`、`_` 能不能构成强调，显示和 Typora 一致：紧挨着中日韩文字时也能开、闭强调（`中_em_文`、`这是**"引号"**。` 都是强调，后者 CommonMark 不算，Typora 1.14.15 实测算）；英文词中间的 `a_b_c` 仍不是（`syntax/emphasis.ts` 替换 Lezer 自带的同名解析器）。

#### I-2 链接与自动链接

- Ctrl+K 插入链接：有选区时变成 `[选区]()`，光标放进地址；没有选区时插入 `[]()`。
- 支持行内链接、引用链接（B-15）、`<https://…>`，以及 S-8「自动链接」打开时的裸网址。
- 打开：Ctrl+单击，或光标在链接上按 Ctrl+Shift+O（N-4）。

#### I-3 行内公式

- `$…$`（S-8「公式」打开时）；「格式 → 行内公式」插入。
- 收起时显示渲染结果；展开时显示源码，下面预览。
- `\$` 是普通的美元符号。

#### I-4 高亮、上标、下标

- `==高亮==`、`^上标^`、`~下标~`，各自由 S-8 的开关控制，默认关闭；「格式」菜单插入。

#### I-5 Emoji

- `:shortcode:` 显示为 emoji（S-8「Emoji」）；shortcode 用 GitHub 的那套（emojibase），可以带 `+`、`-`（`:+1:`，Lezer 自带的不认，换成自己的）。
- 输入 `:` 加字母弹出补全列表（S-5「Emoji 自动完成」：自动触发 / 按 Esc 触发 / 关闭）：↑ ↓ 选择，回车或 Tab 确认，Esc 关闭。
- 列表换成 Element Plus 的弹出框（贴着光标，靠近窗口底边时翻到上面）；候选、键盘处理还是编辑器核心的（@tiptap/suggestion），组件把它的界面回调换掉（`emojiRenderer`）。

#### I-6 行内 HTML、实体与转义

- 行内 HTML（`<span>`、`<kbd>`、`<br>`、`<mark>` 等）收起时显示过滤后的效果，展开时显示标签。
- 实体（`&amp;`、`&#x4E2D;`）收起时显示对应的字符；反斜杠转义收起时不显示反斜杠。

#### I-7 清除格式与样式范围

- 「格式 → 清除格式」Ctrl+\：去掉选区里的行内样式（粗体、斜体、下划线、删除线、行内代码、高亮、上下标）；链接只留文字。
- 样式范围：光标所在的最内层片段，可以选择（Ctrl+E）、删除（E-8）。

### 2.5 表格（T）

#### T-1 插入表格

- Ctrl+T 弹出小窗口，填列数、行数（默认 3 列、2 行），确定后插入；表头为「列 1」「列 2」…。
- 在正文里输入 `| 列 | 列 |` 回车也会生成表格（E-4）。

#### T-2 单元格编辑

- 单元格里直接编辑，行内规则同正文（E-2）。
- Tab、Shift+Tab 到下一个、上一个单元格；最后一格按 Tab 在下面加一行。
- ↑ ↓ 在同一列上下移动；在第一行按 ↑、最后一行按 ↓ 离开表格。
- 单元格里按 Shift+回车插入 `<br>`（Markdown 表格的单元格里不能直接换行）；粘贴的多行文字也换成 `<br>`。
- 竖线 `|` 在单元格里自动写成 `\|`。

#### T-3 行与列

- 「段落 → 表格」：在上方、下方插入行（下方 Ctrl+回车），上移、下移行（Alt+↑ / Alt+↓），删除行（Ctrl+Shift+Backspace）；在左侧、右侧插入列，左移、右移列（Alt+← / Alt+→），删除列；删除表格。
- 拖动行、列的把手移动行、列。

#### T-4 对齐

- 每列可以左对齐、居中、右对齐：「段落 → 表格」或工具条（T-5）；只改分隔行里这一列的 `:`。

#### T-5 工具条与选择

- 光标在表格里时，表格上方显示工具条：对齐、插入和删除行列、删除表格。
- 「段落 → 表格」：选择单元格、选择行、选择列、选择表格；选中的多个单元格可以复制、清空、粘贴。
- 选择行、列、表格是 prosemirror-tables 的单元格选区：行内样式（Ctrl+B 等）、清除格式逐格执行，选中的格子都有这种样式时去掉，否则只给没有的加，空格子不动；退格、删除清空选中的格子；输入的文字换掉选区；回车不处理；按源码改的命令（标题、列表……）不在单元格选区上执行。选择单元格是选中这一格的文字。

#### T-6 粘贴表格数据

- 从 Excel、网页复制的表格（制表符分隔的文字，或 HTML 表格）粘贴到单元格里，从这一格开始按行列填进去，不够时自动加行、加列。
- 粘贴到正文里时生成新的 Markdown 表格（C-3）。

#### T-7 表格源码

- 没改过的表格逐字节不变（通用规则 1）。
- 改过的表格只重写改过的行；新加的行和列按表头行的写法（竖线两边的空格）生成；改了对齐只改分隔行。

### 2.6 图片与媒体（M）

#### M-1 显示

- 支持相对路径（相对文档所在目录；Front Matter 有 `typora-root-url` 时相对它）、绝对路径、`file://`、网址、`data:`。
- 单独成段的图片按块显示、居中；和文字在一起的跟着文字排。导出时同 Typora 包一层 `<span class="md-image">`，主题靠它居中。
- 加载失败时显示失败状态和路径，光标进入后可以改路径。

#### M-2 插入

- 「格式 → 图片 → 插入图片」Ctrl+Shift+I 插入 `![]()`；「插入本地图片...」选文件；把图片文件拖进编辑区；粘贴剪贴板里的图片或图片文件。
- 复制、上传期间先插入占位，完成后换成最终路径；失败时去掉占位并提示原因。
- 写进去的路径按 S-9「自动转义图片 URL」「相对路径添加 ./」处理。

#### M-3 插入时复制到哪里

- S-9「插入本地媒体时」：无特殊操作（直接引用原路径）/ 复制到当前文件夹 / 复制到 `./assets` / 复制到 `./${filename}.assets`，默认 `./assets`。粘贴的图片没有原文件，按同样的位置保存成 PNG。
- 文档还没保存时先要求保存（要知道文档所在目录）；取消就不插入。
- 重名时自动加序号，不覆盖已有文件。
- 「无特殊操作」时粘贴的图片存到 `./assets`（没有原文件可引用）；新文档在这种设置下拖进来的文件直接引用原路径，不要求先保存。已经在目标目录里的文件不再复制。
- 写进去的地址：文档目录里面的写相对路径，外面的写绝对路径，一律用正斜杠；「自动转义」只转空格、括号、`#`、`?`、`%`、尖括号这些会弄坏 Markdown 的字，中文原样。粘贴的图片按时间起名（`image-年月日时分秒毫秒.png`）。

#### M-4 上传

- S-9 配置了上传方式时，插入的图片先上传，用返回的地址：
  - 上传接口：表单 `POST` 上传，Token 放在 `Authorization` 请求头，请求由主进程发出；
  - 自定义命令：运行设置里的命令，把图片路径作为参数，从命令的输出里读地址（同 Typora 的自定义命令上传）。
- Token 加密保存（1.8 节）。
- 只上传图片；上传了就不再复制到文档旁边。粘贴的截图先写进临时文件，传完删掉。请求用 Electron 的 `net.fetch`（走系统代理）；等 60 秒。
- 自定义命令：图片路径按平台加引号接在命令后面，由系统的命令行解释（命令是用户自己填的）；输出里最后一个网址就是地址，退出码不是 0 时报 stderr 的最后一行。

#### M-5 宽度

- 「格式 → 图片 → 设置图片宽度...」：填数字（按 px）或带单位的值，写进这张图片的宽度。

#### M-6 查看大图

- 双击图片打开全窗口查看器：缩放 40%～300%、拖动查看、Ctrl+滚轮缩放、`+` `-` `0` 键、Esc 关闭。

#### M-7 视频与音频

- 插入本地视频、音频文件时写成 `<video controls>`、`<audio controls>`，复制规则同 M-3；编辑区里可以直接播放。

### 2.7 公式与图表（D）

#### D-1 公式渲染

- 用 MathJax 渲染行内公式和公式块，支持 AMS 的环境和符号。
- 化学式 `\ce{}`（mhchem）、physics 宏包。
- 只在进入视口附近时渲染，结果按源码缓存（X-3）。
- 字体：MathJax 4 的 mathjax-newcm 字体把不常用的字符分在 40 个按需加载的文件里（`\mathbb`、`\mathcal`、`\mathfrak`、`\mathscr`、`\mathsf`、`\mathtt`、`\checkmark`、`\ell`、★ 等都在里面，合计 9.9 MB），同步渲染碰到没加载的会失败。`render/mathFonts.ts` 列出每个文件的动态 `import`（打包时各成一块）；同步渲染缺字体时结果标成 `pending`、不进缓存；导出前 `loadMathFonts` 先加载好，编辑时见 `pending` 再加载、重新渲染。
- `\def`、`\newcommand` 之类的定义：整篇渲染时按文档顺序生效（前面定义、后面用）；单个公式的预览只取决于它自己，带定义的公式用一次性的 MathJax 实例渲染，定义不留给别的公式（留在共用的实例里的话，预览结果跟渲染顺序有关，按源码缓存也就不可信）。这些文件一 import 就往字体类上登记，所以字体包必须和 `@mathjax/src` 是同一份：两个都锁定精确版本（4.0.0），`npm ls @mathjax/mathjax-newcm-font` 应是 deduped。
- 构建产物里 MathJax 的字体数据各成一块（动态 import），端到端测试看实际的请求——只有普通公式时不取花体、盲文这些块，打开用 `\mathcal` 的文档时才取花体那一块；打好的安装包里是同一份产物。

#### D-2 公式编号

- S-8「公式自动编号」：不编号 / 只给 AMS 环境编号 / 所有公式块都编号，默认不编号。
- `\tag{}` 自定义编号。
- `\label{}`、`\eqref{}`、`\ref{}` 在整篇范围内引用；编号按文档顺序，导出时一致。

#### D-3 Mermaid

- ```` ```mermaid ```` 不在编辑时显示图表；光标进入时显示源码（CodeMirror），下面实时预览。
- 配色跟主题：深色主题用深色配色。
- S-8 关掉「Mermaid」后按普通代码块显示。

#### D-4 Flowchart 与 Sequence

- ```` ```flow ````（flowchart.js）、```` ```sequence ````（js-sequence-diagrams），显示方式同 D-3；各自有开关（S-8）。
- 「段落 → 图表」插入三种的示例。
- 配色同 D-3 跟主题。js-sequence-diagrams 只有黑线白底，深色主题时沙箱里画完换色；它的框按量出的文字宽度定，默认字体 `"Andale Mono", monospace` 在 Windows 上落到通用的 `monospace`，而 Electron 和浏览器对它选的字体不同，导出的文件换个浏览器打开文字会出框，所以字体写成 `"Andale Mono", Consolas, "Courier New", monospace`。

#### D-5 图表大图查看器

- 双击已渲染的图表，打开全窗口查看器：悬浮工具条放大、缩小、重置；Ctrl+滚轮连续缩放；`+`、`-`、`0` 键；40%～300%；Esc 关闭；不改源码。
- Typora 没有这个功能，保留。
- 双击的第一下按下就选中了这一块：图表块在上面展开源码、图片的 Markdown 标记展开，图被挤开，第二下落在源码、文字上。所以按双击的第一下按在哪张图上打开（第一下按在源码、文字上的双击照常是选词）。端到端测试用 Playwright 真的双击（组件测试直接发 dblclick 事件，测不到这一点）。

#### D-6 渲染失败

- 公式、图表的源码有错时，在原位置显示错误信息和源码，不影响其他内容；编辑时预览里显示错误。

### 2.8 文件与窗口（F）

#### F-1 新建

- Ctrl+N：当前窗口是没改过的空白新文档时就用它，否则新开一个窗口（通用规则 5）。
- 新文档的名字是「未命名.md」（随界面语言）。

#### F-2 新建窗口

- Ctrl+Shift+N 新开一个空白窗口；位置在当前窗口右下错开一点。

#### F-3 打开

- Ctrl+O 选文件；可选的扩展名：md、markdown、mdown、mkd、mkdn、mdwn、mdtxt、mdtext、rmd，也可以选纯文本文件。
- 选窗口的规则（拖放、最近文件、快速打开、系统打开文件、本地链接都用它）：这个文件已经在某个窗口里打开时，切到那个窗口；当前窗口是没改过的空白新文档时，在当前窗口打开；否则新开窗口。
- 文件不存在或读不了时提示原因；从最近文件打开失败时，问要不要从列表里去掉。

#### F-4 快速打开

- Ctrl+P：输入文件名的一部分，从工作区的 Markdown 文件里找，没有工作区时从最近文件里找；↑ ↓ 选择，回车打开（F-3 的窗口规则），Esc 关闭；最多列 30 个。
- 按模糊匹配排序：连续命中、命中词首的靠前，最近打开过的再往前。

#### F-5 最近文件

- 「文件 → 打开最近」列出最近的 20 个；「显示最近文件...」打开面板，可以搜索、打开、从列表移除；「清空最近文件」。
- S-4「记录最近文件」关掉时不记录。
- 所有窗口共用一份（1.8 节）。

#### F-6 保存

- Ctrl+S 保存；新文档按 F-7 处理。
- 原子写入：先写临时文件，再替换原文件；保存到一半断电也不会留下半个文件。
- 冲突检测：保存前比对磁盘上的内容和打开时（或上次保存时）的内容，不一样时提示「文件已被其他程序修改」，可以选：覆盖、载入磁盘上的版本、另存为。
- 换行符、BOM、编码按 E-1、F-18。

#### F-7 另存为

- Ctrl+Shift+S；默认目录是当前文件所在目录，没有时用工作区目录；新文档的默认文件名取第一个标题，没有标题时为「未命名.md」。
- 另存后这个窗口编辑新文件；最近文件里加上新路径。
- 新文档另存时的默认目录：有工作区时用工作区目录，没有时用「文档」目录。

#### F-8 自动保存

- S-3「自动保存」打开时，已经保存过的文档有改动后，按「自动保存间隔」（1、3、5、10 分钟，默认 3）保存。
- S-3「切换文件时自动保存」打开时，在同一窗口里打开别的文件之前先保存。
- 新文档还没有路径，不自动保存，由 F-9 的草稿保护。

#### F-9 草稿恢复

- S-3「恢复未保存的草稿」打开时，每个窗口里没保存的内容（新文档，或改了没保存的文档），在停止输入 1 秒后由主进程写进草稿目录（1.8 节）。
- 程序异常退出、系统重启后再打开 Marko 时，按上次的窗口恢复这些文档和改动，并标出「已从草稿恢复」；原文件在这期间被改过时，提示选用草稿还是磁盘上的版本。
- 正常保存，或在未保存确认里选「不保存」之后，删掉对应的草稿。
- 草稿的路径只收打开过的范围里的（恢复时要读它，1.10 节）；草稿和磁盘上的内容一样时（保存成功但没来得及删）不恢复。S-3 关着时启动时删掉留下的草稿。

#### F-10 未保存确认

- 关闭窗口、退出、在当前窗口打开别的文件、重新载入时，文档有没保存的改动就弹窗：「保存」「不保存」「取消」。
- 退出时有多个窗口没保存，逐个窗口确认，任何一个选「取消」就不退出。
- 退出时挨个窗口问：前一个关掉了再问下一个，问的那个放到最前面；哪个窗口选了取消就停下，后面的不问、不关。

#### F-11 重新载入

- 「文件 → 重新载入」Ctrl+R：从磁盘重新读当前文件；有没保存的改动时先确认（F-10）；光标和滚动位置尽量保留。

#### F-12 外部修改

- 打开的文件被其他程序改了以后：
  - 文档没有没保存的改动：自动重新载入，光标和滚动位置保留，状态栏提示一下；
  - 有没保存的改动：提示「文件已在外部修改」，可以选保留我的改动（之后保存时覆盖）或载入磁盘上的版本。
- 文件被删除或改名后：标题栏标出「已删除」，内容保留，保存时按另存为处理。
- 自己保存引起的变化不算外部修改。
- 主进程盯文件所在的目录（别的程序常用「写临时文件再改名」保存，直接盯文件会跟丢），有动静时读出来算指纹，和窗口记下的（打开、上次保存时的）比；自己保存时主进程先记下新指纹，所以不算外部修改。同一个变化只提示一次。
- Windows 上盯目录前先换成完整的长路径：给 8.3 短路径（`C:UsersABCDEF~1…`）时 Node（libuv）的监听在第一个事件就断言失败，整个主进程退出。
- 选「保留我的改动」以后马上保存不会报冲突：提示还没选完时保存会等它；选择窗口点了按钮就交出结果，不等关闭的动画。
- 自动重新载入的提示放在状态栏（停 5 秒）；状态栏关着时弹出来。

#### F-13 文件操作

- 「文件 → 文件操作」：重命名（只改文件名，扩展名不变）、复制文件路径、在资源管理器（访达）中显示、打开所在文件夹；移到回收站在侧栏的右键菜单里（W-6）。
- 重命名后，窗口跟着编辑新路径，最近文件里的路径跟着改。

#### F-14 系统打开文件

- 安装时登记 Markdown 文件关联（F-3 的扩展名）。
- 在资源管理器、访达里双击，或在命令行运行 `marko 文件路径`，都在已经运行的 Marko 里打开（单实例），按 F-3 的规则选窗口；第一次启动时带的文件在第一个窗口里打开。
- macOS 上拖到程序坞图标、「打开方式」走同样的规则。
- 交给已有的空白窗口打开时把它放到最前面（应用在后台时双击文件要看得到）；参数里的 `file://` 地址也认（Linux 的 .desktop 写的是 `%U`，文件管理器交过来的是地址），见 `main/argv.ts`。

#### F-15 拖放

- 把 Markdown 文件拖到窗口上：按 F-3 打开；拖文件夹：作为工作区打开（W-1）；把图片、视频、音频拖到编辑区：插入（M-2、M-7）。
- 拖动时显示提示：「松开以打开」「松开以插入」。
- 拖进来的文件的路径由预加载脚本用 `webUtils.getPathForFile` 取（只有系统给的文件有路径，网页自己造的取不到），主进程按用户选的放进范围：第一个文件夹作为工作区打开，Markdown 文件第一个按 F-3、其余各开一个窗口；别的文件不管（图片这些由编辑区插入）。拖动时看得到类型看不到文件名：全是图片、视频、音频且在编辑区上时提示「松开以插入」，否则「松开以打开」。

#### F-16 关闭与退出

- 「文件 → 关闭」Ctrl+W 关闭当前窗口，先按 F-10 确认。
- Windows、Linux 上最后一个窗口关掉就退出；macOS 上关掉最后一个窗口程序还在，点程序坞图标新开一个空白窗口。
- 再次启动时，按 S-3「启动时」恢复上次的窗口、文档和工作区，或者新建空白文档。
- 主进程随时记下每个窗口的文档、工作区、侧栏（停 500ms 写一次）：只关掉其中一个窗口时会话里去掉它；退出时、关掉最后一个窗口时留着。命令行带了文件、有要恢复的草稿时不恢复会话。第一个窗口的位置和大小用 `electron-window-state`。
- 窗口都确认、关掉以后由退出流程自己调 `app.quit()`：macOS 上窗口都关了进程还在，不能等 window-all-closed。

#### F-17 窗口标题

- 「● 文件名 - Marko」，有没保存的改动时前面加 ●。
- macOS 上同时设置系统的「已编辑」标记和文档路径（标题栏可以右键看到路径）。

#### F-18 编码

- 打开时识别编码：UTF-8（含 BOM）、UTF-16、GB18030（含 GBK）、Big5、Shift_JIS 等；识别不出时按 UTF-8 打开，并在状态栏提示。
- 「文件 → 以其他编码重新打开」。
- 保存时沿用打开时的编码；新文档用 UTF-8。
- jschardet 把握不大（低于 0.2）的猜测也会给出来，自己再判断一遍；识别不出时状态栏提示「编码识别不出，按 UTF-8 打开」，保存以后就不提示了。不是 UTF-8 的文件在状态栏显示编码。「以其他编码重新打开」有 12 种（UTF-8、UTF-16 LE/BE、GB18030、Big5、Shift_JIS、EUC-JP、EUC-KR、Windows-1252、ISO-8859-1、Windows-1251、KOI8-R），有没保存的改动时同重新载入先问；这种编码的 BOM 照样认。

#### F-19 导入

- 「文件 → 导入...」：用 Pandoc 把 Word（docx）、HTML、EPUB、LaTeX、OpenDocument 转成 Markdown，在新窗口里作为新文档打开。
- 文档里的图片先提取到临时目录，保存时按 M-3 复制到文档旁边。
- 没装 Pandoc 时同 O-4 的提示。
- 图片提取到 `userData/imports/<编号>/`（不用临时目录，保存以后照样引用得到）。
- 保存（保存、另存为）时找出文档里指向导入目录的地址（正斜杠、反斜杠、%20 都认），复制到 M-3 的目录（「无特殊操作」时同粘贴的图片放 `./assets`），地址改成相对路径；主进程把改了哪些地址交回去，编辑器里的内容照着改（光标、滚动位置不变，算已保存）。导入目录放了 30 天以上的启动时清掉。

### 2.9 工作区与侧栏（W）

#### W-1 工作区

- 「文件 → 打开文件夹...」、把文件夹拖到窗口上、侧栏右键「作为工作区打开」、「文件 → 工作区 → 打开所在文件夹为工作区」；「刷新工作区文件夹」「关闭工作区文件夹」。
- 每个窗口有自己的工作区；从一个窗口新开的窗口沿用它的工作区。
- 再次启动时恢复（F-16）。
- 「文件 → 工作区」：打开所在文件夹为工作区（主进程按这个窗口打开的文件取路径，不用渲染进程给）、刷新工作区文件夹、关闭工作区文件夹（不再监听，新窗口也不沿用）。

#### W-2 文件树

- 工作区里的文件夹和 Markdown 文件；文件夹在前，按名称的自然顺序排（`2` 在 `10` 前面）；以 `.` 开头的文件和文件夹不显示。
- 展开、收起；键盘 ↑ ↓ ← → 回车操作；当前文件高亮；「视图 → 在文件树中定位」展开到当前文件。
- 文件夹里有增、删、改名时自动刷新（主进程监听）。
- 在文件树、文件列表（W-3）、搜索结果（W-5）里点文件：在当前窗口里换（F-8、F-10：有改动时按「切换文件时自动保存」先保存，或者问）；文件已经在别的窗口里打开时切到那个窗口。F-3 的选窗口规则不用于侧栏。
- ElTreeV2（虚拟滚动）没有的自己补：数据一变它就按 defaultExpandedKeys 重置展开（工作区一刷新文件夹全收起）——记住展开了哪些交回给它，只给上层都开着的（它会把给的键的上层一起展开）；键盘 ↑ ↓ 移动、→ 展开或进到第一项、← 收起或回到上一层、回车打开文件（焦点留在文件树上）或展开收起；「视图 → 在文件树中定位」展开到当前文件、选中、滚到看得见，不在工作区里时提示。

#### W-3 文件列表

- Ctrl+Shift+2：工作区里所有 Markdown 文件的平铺列表，显示文件名和所在的相对目录；随 W-2 一起自动刷新。

#### W-4 大纲

- Ctrl+Shift+1：按标题生成的树；点标题跳过去；光标所在的标题高亮，跟着光标变。
- S-4「允许折叠大纲」打开时，可以折叠子标题。

#### W-5 全局搜索

- Ctrl+Shift+F：在工作区的 Markdown 文件里搜；结果按文件分组，每条显示行号和那一行的片段，关键字高亮；点一条打开文件（F-3）并跳到那一行。
- 有区分大小写、全词匹配、正则表达式三个开关；边搜边出结果，可以中途取消。
- 没有工作区时提示先打开文件夹。
- 只搜文件树里列的文件（以 . 开头的、node_modules 不搜，不看 .gitignore）；最多列 2000 处、一个文件最多 200 行，超过时提示只列了前面的；输入停下 300ms 后搜，回车马上搜。
- 正则按 ripgrep 的语法（需要环视、反向引用时自动换 PCRE2），和查找栏（JavaScript 正则）大体一致；先在界面里按 JavaScript 检查，写错了直接提示。GBK、GB18030 编码的文件 ripgrep 按 UTF-8 读，里面的中文搜不到（Typora 同样）。
- 一个文件给满 200 行时，文件那一行的数字显示「200+」，鼠标移上去说只列了前面的。

#### W-6 右键菜单

- 文件树、文件列表、最近文件的右键菜单：
  - 文件夹：新建 Markdown 文件...、新建文件夹...、刷新文件夹、作为工作区打开、复制名称、复制相对路径、复制路径、在资源管理器中打开、移到回收站...；
  - 文件：打开、重命名...、复制名称、复制 Markdown 链接、复制相对路径、复制路径、在资源管理器中显示、打开所在文件夹、移到回收站...；
  - 最近文件里的文件再加「从最近文件移除」。
- 移到回收站前确认；移走的正是打开着的文件时，按 F-12「文件被删除」处理。
- 用系统原生菜单（通用规则 6）。
- 侧栏里右键：渲染进程阻止网页默认的菜单，给出菜单项，主进程弹原生菜单（`menu.popup`）交回选了哪项。编辑区、输入框的右键菜单用 `electron-context-menu`，不要「用 Google 搜索」这类外部服务。

#### W-7 侧栏

- Ctrl+Shift+L 显示、隐藏；拖动边缘调宽度，记住宽度。
- 三个页签：文件（文件树 Ctrl+Shift+3、文件列表 Ctrl+Shift+2）、大纲、搜索；打开时默认哪个按 S-4。
- 新窗口沿用打开它的窗口（或最近一次）的侧栏宽度和显示，页签按 S-4「默认侧栏」；恢复会话的照记下的。

### 2.10 查找与跳转（N）

#### N-1 查找

- Ctrl+F 打开查找栏：区分大小写、全词匹配、正则表达式；所有匹配都高亮，显示「第 N 个，共 M 个」；F3 或 Ctrl+G 下一个，Shift+F3 或 Ctrl+Shift+G 上一个；Esc 关闭。
- 在源码上查找，标记字符也能找到；跳到收起的片段里的匹配时，片段展开。
- 选中文字后按 Ctrl+F，查找框里自动填好选中的文字。
- 边输入边跳到光标之后最近的匹配（接着输入时留在原处）；关掉查找栏再打开，上次的文字和开关还在；查找栏关着时按 F3（macOS 是 Cmd+G）打开它。查找栏开着时 F3 由编辑器、查找栏处理，菜单的快捷键不会再走一次（网页先处理按键，没处理的才交给菜单）。

#### N-2 替换

- Ctrl+H 打开替换：替换当前、全部替换；正则时可以用 `$1` 引用分组；全部替换算一步，一次撤销。

#### N-3 跳转

- 「编辑 → 跳转到」：文档开头 Ctrl+Home、文档末尾 Ctrl+End、选区 Ctrl+J（把选区滚到窗口中间）。

#### N-4 链接跳转

- Ctrl+单击链接，或光标在链接上按 Ctrl+Shift+O：
  - 网址、`mailto:`：用系统浏览器、邮件程序打开；
  - 本地 Markdown 文件（相对或绝对路径，可以带 `#标题`）：按 F-3 打开，再跳到标题；
  - `#标题`：跳到本文档的这个标题（锚点规则见 B-2）；
  - 其他本地文件：用系统默认程序打开。
- 侧栏「复制 Markdown 链接」生成相对当前文档的路径。
- 链接的地址原样交给宿主（不像图片那样换成 `marko-asset://` 地址，`#标题` 也要留着），打开时（主进程的 `file.openLink`）：Markdown 文件不受打开过的范围限制（用户点了才会来；页面借它能读的只有 Markdown），按 F-3 打开再跳到 `#标题`（已经在别的窗口里打开的切过去再跳，就是这个文档的原地跳）；文件夹用系统的文件管理器打开；别的文件主进程先问一句（显示完整路径，默认是取消），再用系统默认的程序打开。

### 2.11 视图（V）

#### V-1 专注模式

- F8：只有光标所在的块正常显示，其他块变淡。

#### V-2 打字机模式

- F9：输入和移动光标时滚动页面，让光标所在行保持在窗口的垂直中间（S-6「打字机模式保持居中」）。

#### V-3 状态栏

- S-4「显示状态栏」控制显示；左边是文件路径（新文档显示「尚未保存到磁盘」），右边是字数（S-4「总是显示字数」；有选区时显示选区的字数）；点字数打开 V-4。
- 点字数打开 V-4。选区的字数同 V-4 按显示出来的文字算。

#### V-4 字数统计

- 「视图 → 字数统计...」：词数、字符数、段落数、阅读时间（按 S-4「阅读速度」），选区的词数、字符数、行数，光标所在的行和列。

- 选区：选中的那段原文按 Markdown 解析后数（同整篇，标记、链接地址不算），行数按原文的行。

#### V-5 缩放

- 实际大小 Ctrl+Shift+0、放大 Ctrl+Shift+=、缩小 Ctrl+Shift+-；每次 5%，范围 75%～150%；侧栏、编辑区一起缩放；所有窗口共用一个缩放比例。
- 用 Electron 的页面缩放。

#### V-6 全屏

- F11 全屏；macOS 上是系统全屏。

#### V-7 窗口置顶

- 「视图 → 窗口置顶」：当前窗口保持在其他窗口上面，再点一次取消。

### 2.13 导出与打印（O）

#### O-1 导出 HTML

- 「文件 → 导出 → HTML」：生成自包含的 HTML 文件：用当前主题的样式，公式、图表是预渲染好的 SVG，不引用外网脚本；离线打开和编辑区看到的一样（通用规则 2）。
- 「HTML（不含样式）」：只有结构，不带主题样式；代码块是语义化的 `<pre><code class="language-…">`，不带高亮（同 Typora）。公式的 SVG 要配 MathJax 的样式才排得对，有公式时两种都带上它。
- 图片默认按导出的位置换算相对路径；O-6 里可以选「把图片嵌入文件」。
- 渲染进程按编辑区同一条管线渲染（`@marko/render` 的 `exportDocument`，同一份主题 CSS、同一个图表沙箱），本地图片先写成 `file://` 绝对地址；主进程按导出文件的位置换成相对路径（O-6 选了嵌入时换成 `data:` 地址）。
- 内置主题的字体是应用自己的 `app://` 地址，导出时转成 data URI（`renderer/inlineFonts.ts`）：HTML、PDF、长图、打印拿到应用外面也是同样的字体。图片的相对路径同编辑区：Front Matter 有 `typora-root-url` 时相对它。

#### O-2 导出 PDF

- 「导出 → PDF」：用 O-1 的 HTML 在后台排版，生成 PDF（`printToPDF`）；不需要 Pandoc 和 LaTeX。
- 页面大小、方向、边距、页眉页脚（文档标题、页码）、是否打印背景按 O-6；按标题生成 PDF 书签。
- 在不显示的窗口里打开导出的 HTML（临时文件，本地图片按 `file://` 加载；导出 HTML 的 CSP 不许页面脚本），`printToPDF`。

#### O-3 导出图片

- 「导出 → 图片」：把整篇按 O-1 的样子导出成一张 PNG 长图。
- 同 O-2 的后台窗口按内容高度截图；超过 16000 像素（显卡纹理的上限）时提示改导出 PDF。

#### O-4 Pandoc 格式

- 「导出」里的 Word（docx）、RTF、EPUB、OpenDocument（odt）、LaTeX、reStructuredText、MediaWiki：用 Pandoc 从 Markdown 原文转换。
- 图表先渲染成图片再交给 Pandoc，导出的文档里是图，不是代码。
- 没装 Pandoc 时提示安装方法和下载地址；O-6 里可以指定 Pandoc 的路径和额外参数。
- 图表块（Mermaid、流程图、时序图）交给 Pandoc 前换成图片：渲染进程按序列化时记下的位置把整块换成 `![](名字){width=…px}`（列表、引用里的也行），SVG 交给主进程；主进程在不跑脚本、CSP 不许加载外部资源的后台窗口里按两倍大小截图（在页面里画到画布上不行：Mermaid 的文字在 foreignObject 里，Chromium 会把画布标成不能导出）。Word、ODT、RTF、EPUB 的图片放在临时目录，Pandoc 按 `--resource-path` 找到，导完删掉；LaTeX、reStructuredText、MediaWiki 只写路径，图片放在导出文件旁边的「<文件名>.assets/」里。画不出来的图表留着代码。

#### O-5 打印

- 「文件 → 打印...」Shift+Alt+P：打印 O-1 的排版结果，不打印编辑界面；用系统的打印对话框。
- 同 O-2 的后台窗口调 `webContents.print()`。会弹系统的打印对话框，端到端测试里不测。

#### O-6 导出设置

- PDF：页面大小（A4、Letter 等）、方向、边距、页眉页脚、打印背景、书签。
- HTML：图片引用还是嵌入。
- Pandoc：程序路径、额外参数。
- 导出后：打开文件 / 打开所在文件夹 / 不做什么。

#### O-7 按上次的设置导出

- 「导出 → 按上次的格式导出」：用这个文档上次的格式和保存位置直接导出，不再询问。
- 按文档记在 `electron-store` 里（最多 200 个文档）；直接写的位置只认这个文档上次导出的位置（渲染进程不能指定任意路径）。

#### A-1 内置主题

- 「主题」菜单：SoloLog 浅色、深色；当前的打勾；切换后所有窗口马上生效，编辑区、导出、打印、应用界面都用它。

#### A-2 字体与宽度

- S-2「字体大小」（默认 16）、「内容宽度」（默认 860，正文的最大宽度）。

#### A-3 自定义主题

- 「主题 → 打开主题文件夹」：用户主题目录（1.8 节）；放进去的 `*.css` 自动出现在「主题」菜单里，不用重启；主题文件改了自动重新加载。
- 主题只写 `#write` 下的排版和变量（1.11 节）；主题目录里的 `user.css` 加在任何主题后面，用来做小的调整。
- 支持 Typora 的社区主题：用 Typora 1.14.15 自带的 github、night、newsprint、pixyll、whitey 套我们导出的 HTML（我们的 `base.css` + Typora 的主题），对齐三处后排版、颜色都对：
  1. 代码块的结构和记号类名照 Typora 导出的（CodeMirror 的 DOM、`cm-*`，1.11 节）：用 `<pre><code>` 的话会吃到主题给行内 `code` 的样式，高亮颜色也对不上；
  2. 块之间不输出换行（Typora 的样式让 `li` 保留空白，嵌套列表之间会空出一行）；
  3. `base.css` 放进 CSS 层、变量接上 Typora 的名字（1.11 节）：`#write` 开头的选择器优先级太高的话，night 的深色底和代码配色都盖不过来。
  另外，Typora 主题文件用相对路径引用自己目录里的字体，night 还 `@import` 子样式表——加载用户主题时按主题文件所在目录解析，导出时把 `@import` 展开、字体转成 data URI 内嵌（导出页的 CSP 只许内联样式）；编辑区的代码块（CodeMirror 6）也是同样的类名。Typora 主题里给它自己界面写的样式（侧边栏、文件列表等）不支持。
- 用户主题从 `marko-theme://local/<主题目录里的相对路径>` 加载（只给主题目录里的样式、字体、图片，带 CORS 头）：主题里按相对路径引用的字体、`@import` 的子样式表都能找到。叠在 SoloLog 浅色上面（主题没定义的变量照样有值）；加载完按编辑区的底色判断深浅（`html.dark`、编辑器、图表跟着）。主题目录不递归地盯着，文件增删改了重建菜单、所有窗口重新加载。
- 导出、打印时主题和 user.css 由主进程处理以后内嵌：`@import` 的子样式表展开、按相对路径引用的字体和图片转成 data URI（postcss + postcss-import + postcss-url；postcss-url 按模式动态 require，构建时换成静态的，这一行变了构建就失败），导出的文件离开主题目录也是一样的样子；只处理主题目录里的 .css。

#### A-4 跟随系统深浅色

- S-2「跟随系统深浅色」打开时，系统是深色时用指定的深色主题，浅色时用指定的浅色主题。
- 落点在渲染进程：`matchMedia('(prefers-color-scheme: dark)')` 跟着系统（主进程的 `nativeTheme` 决定它），变了马上换主题。端到端测试切 `nativeTheme.themeSource` 验证（Playwright 默认把页面的 prefers-color-scheme 模拟成浅色，这个测试关掉模拟）。

### 2.16 语言与拼写（L）

#### L-1 拼写检查

- 「编辑 → 拼写检查」开关（和 S-5 是同一个设置）；拼错的词加红色波浪线；代码、公式、网址、HTML 标签里不检查。
- 在拼错的词上右键：菜单最上面是建议的词，点了直接替换；然后是「加入词典」。
- 检查哪些语言在 S-10 里选；Windows、Linux 用 Hunspell 词典，第一次用某种语言时下载，之后离线可用；macOS 用系统拼写。
- 编辑菜单的撤销、重做、全选、粘贴为纯文本按焦点作用：焦点在输入框（查找栏、搜索框）里时作用在输入框上。Windows、Linux 上 Ctrl+Shift+V 由浏览器自己粘贴纯文本，菜单里的快捷键只显示、不注册（不然会粘贴两次）。
- 行内的标记（链接、图片的地址，HTML 标签……）、行内代码、网址、展开的公式源码加了 `spellcheck="false"`，不画波浪线；普通文字、链接文字照常检查。

#### L-2 界面语言

- 中文是默认语言。菜单、对话框、提示、设置的文字都经过 i18n（通用规则 8），加一种语言只要加一份翻译文件，不改代码。
- English 翻译不作为 2.0.0 的发布条件，改动大就先不带（0.4 第 13 条）；带上以后在 S-10 里切换，切换后不用重启。
- 编辑器包里的文字（工具条、提示）由宿主传入（K-2）。
- 翻译放在 `apps/desktop/locales/<语言代码>.json`（主进程、渲染进程共用；`meta.name` 是这种语言自己的名字，S-10 的选项按目录里的文件列出来），加一种语言只要放一份文件。主进程用 vue-i18n 底下的 `@intlify/core-base`，渲染进程用 vue-i18n，消息写法相同；代码里的 `t("a.b")` 路径写错了类型检查报错，偏好设置按设置名拼的路径由单元测试查（每种语言每一项都有字）；每种语言的条目和中文一一对应、每条都能解析也由单元测试查。
- English 带上了；在 S-10 里换，马上生效不用重启：主进程重建菜单（右键菜单下次弹出时换），渲染进程换 vue-i18n 的语言和 Element Plus 的语言（它没有的语言用英文），`<html lang>` 跟着换。设置说明里不给用户看条目编号（「（F-8）」这类）。

### 2.17 编辑器库（K）

#### K-1 对外组件

- 对外的引用方式不变（0.4 第 12 条）：仍然是 `import { MarkoMarkdownBody } from "marko"` 和 `import "marko/style.css"`；导出的类型也不变：`EditorSettings`、`ImageInsertRequest`、`MarkoMarkdownBodyHandle`、`MarkdownExtensionSettings`、`OutlineItem`。
- 仓库根目录的 `package.json` 继续导出这两项，内容由 `prepare` 构建 `@marko/editor-vue` 得到（用 git 依赖安装时也是这样构建）：内部包一起打进产物，第三方依赖保持外部引用。
- 组件的属性、事件、方法不变：
  - 属性：`modelValue`、`readOnly`、`filePath`、`settings`；
  - 事件：`update:modelValue`、`save`、`saveAs`、`open`、`imageData`、`openLink`、`openAnchor`、`outlineChange`；
  - 方法：`replaceImagePlaceholder`、`focus`、`refreshLayout`。
- 产物里没有 Electron、Tauri、Node 的代码。
- 事件 `openLink`：宿主没给 `openLink` 时，本地 Markdown 文件的链接发 `openLink`（按文档的位置解析好的路径，`resolveLocalMarkdownHref`，同 1.x 的库），别的链接发 `openAnchor`。〔和 1.x 不同〕1.x 在富文本块、表格单元格里 Ctrl+单击任何链接都发 `openLink`（原样的地址），2.0 没有这几种块，统一按上面的规则。

#### K-2 宿主接口

- 编辑器需要的外部能力都通过 `EditorHost`：解析本地资源的地址、打开链接、保存粘贴的图片、渲染图表（沙箱）、弹出右键菜单、界面文字。
- 不传时用浏览器里的默认实现：资源地址原样使用、链接在新标签页打开、图片转成 `data:`、右键菜单用浏览器自己的。
- 界面文字：`EditorHost.texts`（编辑器核心：表头「列 n」、链接文本、脚注内容、Front Matter 的 title、图表模板的节点、媒体没插入的提示）、`MarkoEditorHost.texts`（组件：表格工具条、插入表格的小窗口、查看器的按钮、代码语言的提示；对外的类型只用组件包自己的）。读的时候现取，宿主给 getter 就能跟着换语言；不给、给了一部分时其余的用中文（同 1.x 的库）。右键菜单由桌面应用的主进程弹（W-6），不经过 `EditorHost`。

### 2.18 发布（R）

#### R-1 Windows

- x64 的 NSIS 安装包，可以选安装目录；登记文件关联（F-14）；开始菜单快捷方式；每个安装包配 SHA-256 校验文件。
- 只有 @parcel/watcher（原生模块）和 @vscode/ripgrep（带 rg 可执行文件）不打进主进程的产物（其余依赖都打进去，见下面），连同它们运行时要的 picomatch、is-glob、is-extglob、detect-libc 从工作区根目录的 node_modules 带进安装包，各平台的二进制子包写在各平台的 files 里；`.node` 和 rg 解到 asar 外面（`asarUnpack` 按文件名匹配：electron-builder 算不出从根目录拷进来的文件的相对路径）。`npmRebuild: false`（watcher 用 N-API，不用按 Electron 重编译）。
- 打包完的钩子 `build/checksums.cjs` 给每个安装包写 `<安装包>.sha256`（同 sha256sum 的格式）。没有代码签名。
- 主进程的依赖全部打进产物（electron-vite 的 externalizeDeps 关掉），只有 `@parcel/watcher`、`@vscode/ripgrep` 外部引用、由 electron-builder.yml 单独带上；构建完 `apps/desktop/scripts/check-main-bundle.mjs` 检查产物里没有别的外部引用。只靠「哪些依赖要打进去」的名单容易漏：测试用的包放在仓库里时，Node 会往上找到工作区的 node_modules，漏了也查不出来，装到别处主进程就启动失败。
- 在打好的包上跑端到端测试：`npm run test:e2e:packaged`（`scripts/e2e-packaged.mjs`）把包打在仓库外面的临时目录里，只放开 `--inspect` 这一项 Fuse（正式包的 Fuses 不许，Playwright 连不上主进程），设 `MARKO_E2E_EXECUTABLE` 让端到端测试启动它，跑完删掉。

#### R-2 macOS

- Apple Silicon 的 `.dmg` 和 `.zip`；系统版本下限按所用 Electron 版本的要求（0.4 第 9 条）。
- 签名和公证（发给普通用户需要）；登记文件关联（F-14）。
- 二进制子包 darwin-arm64。签名、公证在发布流程里做（`.github/workflows/release.yml`）：配了 `MAC_CSC_LINK`、`MAC_CSC_KEY_PASSWORD` 这两个 secret 用证书签名，再配了 `APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID` 就公证；没配证书时做 ad-hoc 签名（`-c.mac.identity=-`，不开 hardened runtime：ad-hoc 签名没有 Team ID，它的库校验会拒绝加载 Electron 的框架）。不能不签：electron-builder 找不到证书时整个跳过签名，改 Fuses 又改了二进制，原来的签名失效，Apple Silicon 上打不开。ad-hoc 签名的版本第一次打开要在「系统设置 > 隐私与安全性」里确认，也不能自动更新（Squirrel.Mac 要求新版本的签名和装着的版本对得上）。打完包用 `codesign --verify --deep --strict` 校验整个 .app。〔待确认〕还没在 macOS 上实际安装、运行过。

#### R-3 Linux

- x64 的 AppImage 和 deb；用 `.desktop` 文件和 MIME 类型登记文件关联（0.4 第 8 条）。
- 二进制子包 linux-x64-glibc、ripgrep-linux-x64；可执行文件、deb 的包名是 `marko`，deb 的文件名是 `marko_<版本>_amd64.deb`（包名 `@marko/desktop` 不能直接用：文件名默认按它取，带斜杠），deb 的维护者写 `chain-code`。.desktop 的 `%U` 交过来的是 `file://` 地址（F-14）。〔待确认〕还没在 Linux 上实际安装、运行过。

#### R-4 自动更新

- 启动后检查新版本（S-13 可以关）；有新版本时后台下载，下载完提示「重启以更新」；「帮助 → 检查更新」手动检查。
- 更新源是 GitHub Releases。
- electron-updater（打进主进程）：只在安装好的版本里检查；启动后 10 秒检查（S-13 关着不查），有新版本后台下载，下载完问「要重启以更新吗」；「帮助 → 检查更新...」手动检查，有新版本、已经是最新的、出错了都提示。开发时运行、设了 `MARKO_NO_UPDATE` 的版本不检查（测试里不连 GitHub）。electron-builder 的 publish 是 GitHub（生成 latest.yml，安装包里带 app-update.yml）；本地打包 `--publish never`，发布由 CI 做（推版本号标签时，`.github/workflows/release.yml`）：三个平台各自打包，检查产物齐全（安装包、各自的校验文件、更新用的 yml）以后一起放进 GitHub Release；打包、检查失败时把输出的最后几十行写成标注（`.github/scripts/annotate-tail.mjs`），没有仓库管理权限、看不到运行日志也能看到出错的地方。改了打包的配置（这个工作流、`.github/scripts/`、`electron-builder.yml`、`apps/desktop/build/`、`apps/desktop/package.json`）推到 main 时也在三个平台上打一遍包、检查产物，不发布。macOS 用 `macos-latest`（Apple Silicon；不写死版本，旧的镜像会下线）。
- 「重启以更新」先走 F-10 的挨个确认，窗口都关掉了才交给安装程序（安装程序会结束还在运行的应用，不能让它关掉开着的未保存确认框）；取消了不装。

### 2.19 通用要求（X）

#### X-1 不可信文档

- 打开任何 Markdown 文件都不会：执行文档里的脚本；读写用户打开范围以外的文件；在用户没点链接的时候访问网络（远程图片、文档里嵌的网页和音视频除外：同 Typora，网页只许 https，见 M-7 和 1.10 节）。
- 做法见 1.10 节；恶意 HTML、恶意图表、越权路径的样本固定在测试里。
- 接口这一层的范围检查（1.10 节「接口」）包括：渲染进程报上来的文档路径、插入媒体时的原文件、导入图片的路径（规范化以后还要在导入目录里）。`test/e2e/scope.spec.ts` 从页面直接调 `window.marko`，冒充被攻破的页面：越权的路径一律 `out_of_scope`，也不能借文档状态把别的目录放进范围。

#### X-2 离线

- 除了远程图片、图片上传、检查更新、第一次下载拼写词典，所有功能离线可用；渲染和导出不依赖外网。

#### X-3 性能

- 目标（测法见 `test/perf/editor-perf.mjs`；2026-11-24 测：约 10 万字的文档打开约 0.2 秒，移动光标的中位数 1～3 毫秒，输入的中位数 11～16 毫秒，15 次里有 3～7 次超过 16 毫秒，结果在 `test/perf/editor-2026-11-24.json`）：
  - 10 万字（约 4,000 段）的文档，从打开到可以编辑不超过 1.5 秒，不含公式、图表的渲染；
  - 按键到显示不超过 16 毫秒；移动光标不重算全文。
- 公式、图表、图片只在进入视口附近时渲染（1.6 节）。

#### X-4 运行平台

- Windows 10、11 的 x64；macOS Apple Silicon，系统版本下限按所用 Electron 版本的要求；Linux x64。

#### X-5 数据与隐私

- 不收集使用数据；设置、草稿只存在本机（1.8 节）。
- 只有这几种网络请求：远程图片、文档里嵌的网页和音视频、图片上传（用户配置的地址）、检查和下载更新、下载拼写词典。
