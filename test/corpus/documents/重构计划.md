# 重构计划

本文件是 Marko 重构的唯一依据：重构后**怎么做**（第 1 章架构）、**做什么**（第 2 章功能清单，功能编号如 `E-3` 都指它）、每个功能**落在哪**（第 3 章）、**按什么顺序做**（第 4 章）。2026-11-23 定的方向：桌面壳从 Tauri 2 换成 Electron，编辑器内核从 CodeMirror 6 的逐行实时预览换成 ProseMirror 的树形文档，功能对齐 Typora。

使用规则：

1. 重构期间，分层、数据归属、接口、目录的改动**先改本文件第 1 章**，再改代码；代码和本文件不一致时以本文件为准：要么改代码，要么先改本文件。
2. 功能的增、改、删先改第 2 章（编号、要点），再在第 3 章落位到模块，最后才写代码。第 2 章没有编号的功能不写代码；第 1 章没有位置的模块不建文件。
3. 每个功能一个编号，编号不复用；删掉的功能移到第 2 章末尾「已删除」，写明原因。
4. 每条要点都是**验收标准**：每个阶段做完后逐条核对。
5. 标题后带〔新增〕的，是现在没有、重构后要有的；带〔改〕的，是现在有、重构后做法或行为要变的（条目里写明变了什么）；不带标记的是现有功能，重构后行为不变。
6. 条目没写到的交互细节，以阶段 0 从现有测试里提取的行为规格（4.3 节）和 Typora 1.13.7 的默认行为为准；两者冲突时，在条目里写明取哪个。
7. 文中的 `Ctrl` 在 macOS 上是 `Cmd`，`Alt` 是 `Option`。

### 0.2 为什么重构

1. **用逐行的源码编辑器去模拟 Typora 的树形文档。** CodeMirror 6 的每一行是一个 `div.cm-line`，表达不了嵌套、外边距折叠、有序编号和表格布局，只能在 JS 里重新算：块间距和折叠约 520 行（`ContinuousMarkdownEditor.vue:1228-1750`）、列表符号和编号约 340 行（`:1781-2117`）、点击和拖选换算回源码位置约 2,000 行、表格在 Widget 里另起一个 Vue 应用和单元格编辑器约 5,100 行。指针换算的回归测试有 12 个文件，间距和块边界的有十来个。
2. **一份文档几套解析**，块边界要靠互相对齐，对不齐就是回归。
3. **每次按键、每次移动光标都做全文计算**：装饰依赖 `selection`，每次都对全文 `split("\n")` 重建；内容一变还要另做一次非增量的完整解析；每次按键把全文发给 `App.vue`，同步重算大纲、统计、查找，再把全文写进 localStorage。
4. **职责堆在几个巨型文件里**，依赖方向混乱（`markdownLinks` 依赖编辑器的 `editorBlocks`，`editorCommands` 依赖渲染层 `markdown`），编辑器组件直接依赖 Tauri。
5. **安全边界缺失**：CSP 为 `null`；资源协议范围是 `["**"]`；`read_text_file`、`write_text_file`、`trash_path` 接受任意路径；Mermaid 设成 `securityLevel: "loose"`，SVG 直接写进 `innerHTML`；发布版开着开发者工具。
6. **桌面行为不全**：只有一个窗口；不监听外部修改；PDF 导出要装 LaTeX；拼写检查看不到建议；主题写死两套；界面只有中文；`main.rs` 没有处理 macOS 的 `RunEvent::Opened`（从访达打开文件走的是这个事件）。
7. **测试锁死源码文本**：至少 29 个测试文件读取 `.vue`、`.css` 源码，用正则断言 CSS 规则和代码原文，拆文件、改名就成片失败。

### 0.3 目标

- 功能对齐 Typora（第 2 章）；Marko 已有、Typora 没有的（如图表大图查看器 D-5）保留。
- 打开、不改、保存逐字节不变；改一处只影响那一块（E-1）。
- 编辑区、导出、打印用同一份主题 CSS 和同一条渲染管线，所见即所得。
- 打开任何来路不明的 Markdown 文件都不会执行脚本、越权读写文件（X-1）。
- 支持 Windows x64、macOS Apple Silicon、Linux x64（R 章）。

### 0.4 已定的事（2026-11-23）

1. 桌面壳从 Tauri 2 换成 Electron。
2. 编辑器内核换成 ProseMirror 的树形文档，DOM 结构和 Typora 一致；Lezer 是唯一的结构解析器；代码块、公式块、HTML 块、Front Matter 和整篇的源码模式用 CodeMirror 6。
3. 文本块里保留行内 Markdown 原文，语法标记用装饰隐藏，光标进入时显示（1.5、1.6 节）。
4. 无损序列化：没改过的块原样输出原始源码片段（1.5 节）。
5. 应用外壳用 Vue 3；编辑器内核不依赖任何框架。
6. 不考虑工程量，只按合理性定方案。
7. 现有测试里「文本 + 选区 → 文本 + 选区」形式的期望，迁移成新架构的行为规格；读取源码文本做断言的测试不迁移。
8. 支持 Linux x64（R-3）。
9. macOS 跟着最新的 Electron 走：系统版本下限按所用 Electron 版本的要求，不为旧系统单独兼容；安装包只出 Apple Silicon，同现在（R-2）。
10. 不导入旧版本（Tauri）的设置、最近文件和未保存的草稿：它们存在 WebView2 / WKWebView 的 localStorage 里，Electron 读不到。2.0.0 的发布说明提醒用户升级前先保存所有文档。
11. Typora 社区主题看难易：阶段 3 用几个常用的 Typora 主题试一遍，只需对齐类名、补少量兼容样式就顺手支持，改动大就不做（A-3）。
12. 编辑器库对外的引用方式、导出的类型、组件的属性、事件和方法都保持不变（K-1）。
13. 中文是默认界面语言，界面文字从一开始都经过 i18n；English 翻译不作为发布条件，改动大就先不做（L-2）。

### 1.1 总则

1. **Markdown 文件是唯一的持久化格式。** 打开、不改、保存逐字节不变；改一处只影响那一块（E-1）。
2. **一件事只有一个来源。** 一个解析器（Lezer）、一套高亮（Lezer）、一份主题 CSS、一条渲染管线；编辑、导出、打印、复制为 HTML 都用它们。
3. **屏幕上显示的就是 Markdown 的真实含义。** 任何时刻 `parse(serialize(doc))` 都和 `doc` 结构相同（1.5.5）。
4. **依赖只朝一个方向**（1.4 节），用包边界和 dependency-cruiser 检查，循环依赖是错误。
5. **每类数据只有一个主人**（1.8 节）。文件、设置、最近文件、草稿都归主进程；渲染进程只通过预加载脚本暴露的 `window.marko` 读写。
6. **不信任文档内容**（1.10 节）。文档里的 HTML、图表、链接都按不可信内容处理；渲染进程拿不到 Node；涉及路径的接口都检查范围。
7. **编辑器不依赖桌面。** 编辑器包只通过 `EditorHost` 接口获取资源地址、打开链接、保存图片、渲染图表，可以单独在浏览器里用（K 章）。
8. **第 2 章的每个编号都能在第 3 章找到归属模块**；找不到的，要么补文档，要么不写代码。

### 1.2 进程模型

| 进程 | 做什么 | 能用什么 |
|---|---|---|
| 主进程（`apps/desktop/main`） | 窗口、原生菜单和右键菜单、文件读写和监听、工作区、全局搜索、图片和媒体、导出、拼写检查、设置和草稿的持久化、单实例和系统打开文件、自动更新 | Node、Electron 主进程 API |
| 预加载脚本（`apps/desktop/preload`） | 用 `contextBridge.exposeInMainWorld` 暴露 `window.marko`（1.9 节），不暴露 `ipcRenderer` 本身 | `contextBridge`、`ipcRenderer` |
| 渲染进程（每个窗口一个） | 应用界面（Vue）和编辑器 | 浏览器 API 和 `window.marko`；`contextIsolation`、`sandbox` 打开，`nodeIntegration` 关闭 |
| 图表沙箱（每个窗口里一个隐藏的 iframe） | 运行 Mermaid、flowchart.js、js-sequence-diagrams，把源码变成 SVG | 只有 `postMessage`。带 `sandbox="allow-scripts"`、不带 `allow-same-origin`，源是不透明的：读不到父页面，没有 `window.marko`，CSP 禁止联网 |
| 导出页（按需创建的隐藏窗口） | 加载要导出的自包含 HTML，供 `printToPDF`、`capturePage`、`print` 使用 | 只有 HTML 和 CSS；没有预加载脚本，禁止脚本 |

### 1.5 文档模型

#### 1.5.1 解析

- 用 `@lezer/markdown` 加 1.3 节的扩展解析整篇；编辑后只增量解析改动的范围。
- 每个块记下两样东西：
  - **原始片段**：这一块在文件里的原文（含块前的空行）；
  - **写法**：同一种语法的选择，如列表符号（`-`、`*`、`+`）、序号分隔符（`.`、`)`）、起始序号、松紧；强调字符（`*`、`_`）；围栏字符和长度、信息串；标题是 ATX 还是 Setext、ATX 结尾的 `#`；引用每行的前缀；缩进宽度。

#### 1.5.2 节点

| 节点 | Markdown | 内容 | 写法属性 |
|---|---|---|---|
| `doc` | 整篇 | 块 | 末尾换行、换行符、BOM、编码 |
| `paragraph` | 段落 | 行内原文 | — |
| `heading` | 标题 | 行内原文 | 级别、ATX / Setext、结尾的 `#` |
| `blockquote` | `>` 引用 | 块 | 每行的前缀 |
| `alert` | `> [!NOTE]` 等 | 块 | 种类、标题行原文 |
| `bulletList`、`orderedList` | 列表 | 列表项 | 符号 / 起始序号和分隔符、松紧 |
| `listItem` | 列表项 | 块 | 任务状态（无 / 未完成 / 已完成）、缩进 |
| `codeBlock` | 围栏、缩进代码 | 纯文本 | 围栏字符和长度、信息串、是否缩进代码 |
| `diagram` | mermaid / flow / sequence 围栏 | 纯文本 | 同 `codeBlock` |
| `mathBlock` | `$$…$$` | 纯文本 | 分隔符的写法 |
| `htmlBlock` | HTML 块 | 纯文本 | — |
| `frontMatter` | 开头的 `---` YAML | 纯文本 | — |
| `toc` | `[TOC]` | 无 | 原文 |
| `table`、`tableRow`、`tableHeader`、`tableCell` | GFM 表格 | 单元格是行内原文 | 每列的对齐、分隔行原文、每行的原文 |
| `horizontalRule` | `---`、`***`、`___` | 无 | 原文 |
| `footnoteDefinition` | `[^id]: …` | 块 | 标签 |
| `referenceDefinition` | `[id]: 地址 "标题"` | 纯文本 | — |
| `definitionList`、`definitionTerm`、`definitionDescription` | 定义列表 | 行内原文 / 块 | 冒号后的写法 |

图片、链接、脚注引用、行内公式、行内 HTML 都在行内原文里，不是节点。

#### 1.5.3 行内原文

- 文本块的内容就是这一块的行内 Markdown 原文：`**粗体**` 在文档里就是这 6 个字符；软换行是 `\n`；引用、列表的前缀不在文字里。
- `markdown/inline.ts` 把原文切成片段（类型、标记位置、内容范围、嵌套关系）。编辑器按片段加装饰（1.6 节），渲染按同样的片段输出 HTML，两边对一段原文的理解永远一致。
- DOM 里的文字就是源码，所以光标位置天然对应源码位置，点击、拖选不需要换算。

#### 1.5.4 序列化

- 块没被改过时，输出它的原始片段。
- 改过的块按写法属性重新生成；这一块里没改的行沿用原来的前缀和缩进；新加的行、项、单元格按同一块里第一行（项、单元格）的写法生成。
- 新建的块用默认写法：列表 `-`、强调 `*`、加粗 `**`、围栏 ```` ``` ````、分隔线 `---`、ATX 标题；块与块之间一个空行。

#### 1.5.5 不变式

- `parse(serialize(doc))` 和 `doc` 结构相同。
- 每次事务后，`plugins/reconcile.ts` 把改动涉及的块（连同前后各一个块）序列化再解析；结构不同时用解析结果替换这几个块，选区按源码偏移换回去。例：在段落下一行输入 `===`，段落变成一级标题；在列表项里输入使它不再是列表项的内容，块跟着变。
- 输入法组合期间不做（E-12），组合结束后补做。
- 调试构建里每次事务后检查一遍整篇；随机编辑的模糊测试检查同一条（1.13 节）。

#### 1.5.6 位置换算

- `markdown/positions.ts` 在文档位置和源码偏移之间换算；源码模式切换（E-11）、查找（N-1）、外部修改的合并（F-12）、状态栏的行列（V-4）、跳到搜索结果的行（W-5）都用它。

### 1.6 编辑器

- **行内装饰**（E-2）：光标在片段里或紧挨着片段边界时，片段「展开」，标记显示出来；否则标记隐藏。原子片段（行内公式、emoji、脚注引用、行内 HTML、图片、实体）收起时用 Widget 装饰显示渲染结果，原文还在文字里。片段按文本块缓存，只在这个文本块变了时重新切；光标移动只更新新旧两处片段的装饰，不重算全文。
- **块级标记**（E-3）：不在文字里，由节点渲染：标题是 `h1`～`h6`，列表是 `ul` / `ol` / `li`，任务框是复选框，引用是 `blockquote`。
- **NodeView**：
  - 代码块总是一个 CodeMirror 6 编辑器（同 Typora）；
  - 公式块、HTML 块、图表不在编辑时显示渲染结果，光标进入时显示 CodeMirror 源码，公式和图表在下面实时预览；
  - Front Matter 总是 YAML 编辑器；
  - 表格用 prosemirror-tables，单元格是普通文本块，行内规则同正文。
- **光标在原子块之间**：用 gapcursor，代码块、表格、公式块前后都能放光标并输入。
- **源码模式**（E-11）：一个 CodeMirror 6 视图编辑整篇源码。进入时序列化；退出时解析，只替换变了的块；选区按源码偏移换算。
- **大文档**（X-3）：公式、图表、图片进入视口附近才渲染，结果按源码缓存；装饰和语义层都只更新改动的块。

### 1.7 渲染与导出

- 一条管线：文档模型 → `render/html.ts` → HTML → 主题 CSS。编辑区里的预览（行内 Widget、NodeView 里的预览）调同一批函数（`math`、`highlight`、`diagrams`、`sanitize`）。
- 图表：编辑器把「类型 + 源码 + 主题」交给 `render/diagrams.ts`；它通过 `postMessage` 交给图表沙箱（1.2 节），沙箱返回 SVG，过滤一遍再插入，按源码缓存。图表库的全局变量（jQuery、Raphael）只存在于沙箱里。
- 公式：MathJax 渲染成 SVG。自动编号、`\label`、`\eqref` 需要按文档顺序统一处理，编号状态由 `render/math.ts` 按整篇管理，单个公式改动时只重排受影响的编号。
- 导出（O 章）：渲染进程用 `render/exportDocument.ts` 生成自包含 HTML，交给主进程：
  - HTML：直接写文件；
  - PDF、打印、图片：主进程在隐藏的导出页里加载这份 HTML，再 `printToPDF`、`print`、`capturePage`；
  - Word 等 Pandoc 格式：主进程调用 Pandoc；图表先渲染成图片，换掉代码块再交给它。

### 1.8 数据：存在哪、谁是唯一来源

「主人」是唯一能写它的地方。`userData` 指 Electron 的 `app.getPath("userData")`。

|---|---|---|---|
| 文档 | 用户的文件系统 | `.md` 文件 | 主进程 `files.ts` 读写：原子写入（临时文件 + 改名），写之前比对磁盘内容（F-6） |

### 1.9 主进程接口

### 1.10 安全

- **渲染进程**：`contextIsolation`、`sandbox` 打开，`nodeIntegration` 关闭；只有 `window.marko`；`will-navigate` 和 `setWindowOpenHandler` 拦下一切页面跳转和新窗口，链接都走 N-4。
- **CSP**（`protocol.ts` 给应用页面加的响应头）：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' marko-asset: data: blob: https: http:; media-src marko-asset: blob: https: http:; connect-src 'self'; frame-src 'self' https:; object-src 'none'; base-uri 'none'`。上传、更新检查都由主进程发请求，渲染进程不需要联网。
- **本地资源**：`marko-asset://` 只返回图片、视频、音频类型的文件，其他类型一律拒绝。
- **接口**：涉及路径的调用都过 `scope.ts`。范围是用户主动打开过的：对话框选的、拖进来的、命令行和系统打开的文件，最近文件，工作区目录，以及这些文档所在目录下按 M-3 写入的资源目录。不在范围内返回 `out_of_scope`。
- **文档里的 HTML**：经 `render/sanitize.ts` 过滤后插入：去掉 `<script>`、事件属性、`javascript:` 地址、`<object>`、`<embed>`、表单；`<iframe>` 只保留 `https:` 地址，并加上 `sandbox` 属性；`<video>`、`<audio>`、`<details>`、`<img>`、`<kbd>` 等常用标签保留。
- **图表**：在沙箱里渲染，返回的 SVG 再过滤一遍；Mermaid 用 `securityLevel: "strict"`。
- **外部链接**：只允许 `http:`、`https:`、`mailto:` 交给 `shell.openExternal`。
- **开发者工具**：发布版只在「帮助 → 开发者工具」（R-6）手动打开。
- **Electron Fuses**：关闭 `RunAsNode`、`EnableNodeOptionsEnvironmentVariable`、`EnableNodeCliInspectArguments`；打开 `EnableEmbeddedAsarIntegrityValidation`、`OnlyLoadAppFromAsar`。
- 每次发布前按本节逐条检查；X-1 的回归用例（恶意 HTML、恶意图表、越权路径）在测试里固定下来。

### 1.11 主题与样式

- 编辑区的根元素是 `#write`，块和行内都是普通 HTML 元素：`h1`～`h6`、`p`、`blockquote`、`ul`、`ol`、`li`、`table`、`pre`、`code`、`img`、`a`、`strong`、`em`。导出的 HTML 结构和类名相同，所以同一份主题 CSS 两边都适用。
- 编辑时才有的东西（展开的标记、NodeView 的边框、工具条、选中的单元格）用 `md-` 开头的类名，写在 `editor.css`，不进导出。
- 主题只写 `#write` 下的排版和 `:root` 上的变量；应用界面用 `ui.css` 的 `--marko-ui-*` 变量，主题可以覆盖这些变量来切深浅色。
- 代码高亮的颜色由主题给出，CodeMirror 编辑器和静态高亮用同一套类名。
- 组件里不写死颜色、字号、字体，都用变量。

## 2 功能清单

### 2.0 术语

| 术语 | 含义 |
|---|---|
| 文档 | 一个 Markdown 文件，或还没保存的新文档 |
| 块 | 段落、标题、引用、列表、表格、代码块等块级元素 |
| 文本块 | 直接装文字的块：段落、标题、表格单元格、定义列表的词条 |
| 行内原文 | 文本块里存的这一块行内内容的 Markdown 原文，含 `**`、`` ` ``、`[]()` 等标记 |
| 片段 | 行内原文里的一个语法单元：粗体、链接、行内公式等 |
| 展开 / 收起 | 片段显示出 Markdown 标记 / 只显示排版结果 |
| 原子片段 | 收起时用渲染结果代替显示的片段：行内公式、emoji、脚注引用、行内 HTML、图片、HTML 实体 |
| 写法 | 同一种语法的不同写法，如列表符号用 `-` 还是 `*`、强调用 `*` 还是 `_`、围栏用几个反引号 |
| 工作区 | 侧栏里打开的文件夹 |
| 源码模式 | 整篇以 Markdown 源码编辑的模式 |

### 2.1 通用规则

有几条规则管着很多功能，在这里各写一次，各条目只引用（写作「通用规则 N」）。

1. **无损**（E-1）：打开、不改、保存逐字节不变；改一处只影响那一块，沿用这一块原来的写法。
2. **所见即所得**（A 章、O 章）：编辑区、导出、打印、复制为 HTML 用同一份主题 CSS 和同一条渲染管线。
3. **显示就是含义**：编辑后，块的结构总是和这份 Markdown 重新解析的结果一致（1.5.5）。
4. **撤销**（E-6）：所有修改都能撤销，包括自动转换、表格操作、图片插入、代码块和公式块里的修改、源码模式里的修改。
5. **一个窗口一个文档**（F-1～F-3）：同一个文件只在一个窗口里打开；设置改动所有窗口同时生效。
6. **菜单**：每个命令都在原生菜单里，显示快捷键；编辑区、侧栏的右键菜单也是原生菜单（W-6、L-1）。
7. **不可信内容**（X-1）：文档里的 HTML、图表、链接都按不可信内容处理。
8. **界面文字**（L-2）：菜单、对话框、提示、设置的文字都可以翻译，代码里不写死某一种语言。
9. **输入法**（E-12）：输入法组合期间不做任何自动处理，上屏后再处理。

### 2.2 编辑核心（E）

#### E-1 无损读写〔改〕

- 打开后不做任何修改就保存，文件逐字节不变：换行符、空行、缩进、列表符号、强调字符、围栏、表格的竖线和空格、HTML、实体都不变。
- 改了某一块，其他块逐字节不变；改过的块沿用原来的写法（列表符号、序号分隔符、强调字符、围栏字符和长度、缩进宽度），这一块里没改的字符也不变。
- 换行符沿用文件原来的；改过的块用文件里出现最多的那种；新文档用 S-3 的「默认换行符」。S-3「保存时插入末尾换行」打开时，保存时末尾补一个换行。
- 带 BOM 的文件保存时保留 BOM；编码见 F-18。
- 〔改〕现在保存时按设置统一换行符：「默认换行符」是「自动」时，在 Windows 上打开 LF 的文件，不改内容直接保存也会变成 CRLF。

#### E-2 行内语法的显示与编辑〔改〕

- 光标在一个片段里面，或紧挨着它的边界时，这个片段展开，显示它的标记（`**`、`*`、`~~`、`` ` ``、`[文字](地址)`、`$`），可以直接改标记；光标离开就收起，只显示排版结果。
- 片段嵌套时（如粗体里的链接），光标所在的每一层都展开。
- 原子片段收起时显示渲染结果（公式、emoji、脚注序号、过滤后的 HTML、图片、实体对应的字符）；展开时显示原文，行内公式和图片在原文旁边显示预览。
- 单击、拖选收起的文字时，光标落在点到的那个字符上。
- 链接收起时，单击只放光标，Ctrl+单击打开（N-4）。
- 〔改〕现在收起的内容是替换成渲染结果的 Widget，点击位置要换算回源码（约 2,000 行代码）；重构后文字就是原文，不需要换算。

#### E-3 块级标记

- 标题的 `#`、列表符号、任务框、引用的 `>`、代码块的围栏不出现在文字里，由块本身呈现：标题字号、列表圆点和序号、复选框、引用左边的竖线。
- 改块的类型用菜单、快捷键（B 章各条）或自动转换（E-4）。
- 文本块开头按退格：标题变正文；列表项变正文，再按一次并入上一块；引用、Callout 里的第一段移出来。

#### E-4 自动转换

- 在正文段落开头输入下面的内容，段落马上变成对应的块（通用规则 9）：

  | 输入 | 变成 |
  |---|---|
  | `# `～`###### ` | 一到六级标题 |
  | `> ` | 引用 |
  | `- `、`* `、`+ ` | 无序列表 |
  | `1. `、`1) `（任意起始数字） | 有序列表 |
  | `- [ ] `、`- [x] ` | 任务列表 |
  | `> [!NOTE]` 等五种 + 回车 | Callout（B-13） |
  | ```` ``` ```` 或 `~~~`，后面可以跟语言，+ 回车 | 代码块（B-6）；没写语言时按 S-7 的默认语言 |
  | ```` ```mermaid ````、```` ```flow ````、```` ```sequence ```` + 回车 | 图表（D-3、D-4） |
  | `$$` + 回车 | 公式块 |
  | `---`、`***`、`___` + 回车 | 分隔线 |
  | `\| 列 \| 列 \|` + 回车 | 表格（T-1） |
  | `[TOC]` + 回车 | 目录 |
  | 文档第一行的 `---` + 回车 | YAML Front Matter |
  | `[^id]: ` | 脚注定义 |

- 段落的下一行（软换行后）输入 `===` 或 `---`，段落按 Markdown 的规则变成 Setext 标题（通用规则 3）。
- 转换后马上按 Ctrl+Z，撤回转换，留下输入的字符。

#### E-5 回车、退格与 Tab

- 回车：
  - 正文、标题里拆成两块；标题末尾回车，下面新开一个正文段落；
  - 列表项里新建同级的项（任务列表的新项不勾选）；空的列表项上回车，项向外缩一级，最外层时变成正文；
  - 引用、Callout 里拆段后还在里面；空段落上回车退出引用。
- Shift+回车：段落里换行（软换行）。软换行的显示按 S-6「保留单个换行」。
- 退格：见 E-3；自动配对的符号中间按退格，两个一起删（E-9）。
- Tab、Shift+Tab：列表项缩进、反缩进（宽度按 S-5「Markdown 缩进宽度」）；表格里到下一个、上一个单元格（T-2）；代码块里按「代码缩进宽度」缩进（B-6）；其他位置按 S-5「Shift+Tab 自动缩进」。

#### E-6 撤销与重做

- Ctrl+Z 撤销；Ctrl+Y 或 Ctrl+Shift+Z 重做。
- 整篇共用一条历史（通用规则 4）；代码块、公式块里的 CodeMirror 编辑也进同一条历史。
- 连续输入合并成一步；停顿 3 秒以上另起一步。
- 切换源码模式不清空历史（E-11）。

#### E-7 选择

- Ctrl+A 全选整篇；光标在代码块、公式块里时，第一次只选这一块的内容，再按一次选整篇。
- 「编辑 → 选择」：当前词 Ctrl+D、样式范围 Ctrl+E（I-7）、当前句子、当前行 Ctrl+L、当前段落。
- 双击选词，三击选整个文本块。
- 可以跨块拖选；选区里的代码块、公式块、表格整块选中。

#### E-8 删除与移动

- 「编辑 → 删除」：当前词 Ctrl+Shift+D、当前句子、样式范围、当前段落。
- 「编辑 → 行操作」：复制当前行、删除当前行 Ctrl+Shift+Backspace、上移 Alt+↑、下移 Alt+↓。在排版视图里，「行」指光标所在的块：列表项按项、表格按行（T-3），其他按整块；源码模式里按行。

#### E-9 自动配对

- S-5「自动配对」打开时，输入左半边自动补右半边：`(`、`[`、`{`、`"`、`'`、`` ` ``、`$`，以及中文的 `（`、`【`、`《`、`「`、`『`、`“`、`‘`。
- 有选区时输入上面的符号，或 `*`、`_`、`~`，把选区包起来。
- 光标后面正好是要输入的右半边时，直接跳过它；光标在一对符号中间按退格，两个一起删。

#### E-10 智能标点

- S-6「智能引号」「智能破折号与省略号」打开时，只改显示：直引号显示成弯引号，`--`、`---` 显示成破折号，`...` 显示成省略号；文件里还是原来的字符（通用规则 1）。
- 代码、公式、网址、HTML 里不处理。

#### E-11 源码模式

- Ctrl+/ 切换；整篇用 CodeMirror 6 编辑 Markdown 源码，带 Markdown 语法高亮，代码块里的代码按语言高亮。
- 切换时光标、选区和滚动位置按源码偏移保留（1.5.6）。
- 源码模式下查找、替换、大纲、字数统计照常。
- 撤销历史跨模式连续（E-6）。

#### E-12 输入法

- 输入法组合期间：片段不展开也不收起，不做自动转换、自动配对、emoji 补全、不变式的重新解析；上屏后按上屏的文字处理。
- 任何文本块里都能组合输入（含表格单元格、标题、列表项、引用、Callout），候选框跟着光标。

### 2.3 块（B）

#### B-1 段落与换行

- Ctrl+0 把当前块变成正文段落。
- 软换行（E-5）、硬换行（行尾两个空格或 `\`）按 Markdown 显示，源码保持原样。

#### B-2 标题

- 一到六级：Ctrl+1～Ctrl+6；Ctrl+= 提升、Ctrl+- 降低一级。
- ATX（`#`）和 Setext（下划线 `===`、`---`）都支持，改级别时沿用写法；Setext 只有一、二级，改到三级以下时换成 ATX。
- 每个标题有锚点 id，规则和 Typora 一致，文档内链接 `[x](#标题)` 在两边都能跳；目录、大纲、导出的 HTML 用同一个 id。

#### B-3 引用

- Ctrl+Shift+Q 把当前块放进引用，或移出引用；可以嵌套；里面可以放任何块。
- 懒惰续行（下一行没写 `>`）按 Markdown 规则属于这个引用；没改过的行保存时不补 `>`（通用规则 1）。

#### B-4 列表

- 无序 Ctrl+Shift+]、有序 Ctrl+Shift+[；缩进 Ctrl+] 或 Tab，反缩进 Ctrl+[ 或 Shift+Tab。
- 有序列表显示的序号按 Markdown：从第一项的数字开始，依次加一。插入、删除、移动项之后，后面各项源码里的数字改成连续的，分隔符（`.` 或 `)`）沿用。
- 紧凑列表和松散列表（项之间有空行）按原样显示和保存。
- 有序列表的项也可以是任务（`1. [ ] `）。

#### B-5 任务列表

- Ctrl+Shift+X 把当前块变成任务列表；点复选框切换 `[ ]` 和 `[x]`；「段落 → 切换任务状态」切换光标所在的项。
- 勾选只改方括号里的那一个字符。

#### B-6 代码块

- Ctrl+Shift+K 插入；```` ``` ````、`~~~` 围栏和缩进代码块都显示为代码块，保存时保持原写法。
- 代码块总是一个 CodeMirror 编辑器，按语言高亮；高亮用 Lezer，和导出、打印的一致（通用规则 2）。
- 语言：代码块右上角显示语言，点开可以搜索、选最近用过的；改语言只改围栏后面的信息串。
- 默认语言（S-7）：不指定 / 最近使用 / 固定语言；「应用时机」决定通过 Markdown 输入（E-4）、通过菜单插入时是否套用。
- 显示行号、长代码自动换行按 S-7；Tab 按「代码缩进宽度」。
- 右键菜单：复制代码块内容、为选中内容调整缩进、为整个代码块调整缩进。
- 在最后一行按 ↓、第一行按 ↑ 离开代码块；文档以代码块结尾时，在最后一行按 ↓ 在后面新建正文段落。

#### B-7 公式块

- Ctrl+Shift+M 插入 `$$` 公式块（S-8「公式」打开时）。
- 不在编辑时显示渲染结果；光标进入时显示源码编辑器（CodeMirror，LaTeX 高亮），下面实时预览。
- 渲染见 D-1，编号见 D-2，出错见 D-6。

#### B-8 分隔线

- 「段落 → 分割线」插入 `---`；`***`、`___` 等写法保持原样。

#### B-9 YAML Front Matter

- 只能在文档开头；「段落 → YAML Front Matter」插入，或在文档第一行输入 `---` 回车（E-4）。
- 显示为 YAML 编辑器（CodeMirror，YAML 高亮）；不属于正文，不导出成正文内容。
- `typora-root-url` 键决定图片相对路径的根目录（M-1）。

#### B-10 目录 [TOC]

- 单独一段 `[TOC]` 显示为按标题生成的目录，随标题实时更新；点条目跳到标题。
- 「段落 → 目录 [TOC]」插入；导出时一起输出。

#### B-11 脚注

- 引用 `[^id]` 显示为上标序号，按在文中第一次出现的顺序编号；鼠标移上去显示脚注内容；点击跳到定义。
- 定义 `[^id]: 内容` 在原位置显示，带回到引用处的链接，多处引用时每处一个。
- 引用了但没有定义的，点击时在文末新建定义。
- 「段落 → 脚注」在光标处插入引用，并在文末新建对应的定义。

#### B-12 HTML 块与注释

- HTML 块不在编辑时显示过滤后的渲染结果（X-1）；光标进入时显示源码（CodeMirror，HTML 高亮）。
- `<video>`、`<audio>`、`<details>`、`<img>` 等照常显示；`<iframe>` 只显示 `https:` 地址的，并放进沙箱（1.10 节）。
- 「格式 → 注释」Ctrl+Shift+/ 把选中的内容包成 `<!-- -->`；注释在编辑区以灰色显示原文，导出时不输出。

#### B-13 Callout

- `> [!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` 显示为带图标和标题的提示框；「段落 → Callout / Alert」插入五种之一。
- 光标进入标题行时显示 `[!NOTE]` 原文，可以改种类；框里可以放任何块。

#### B-14 定义列表

#### B-15 链接引用定义〔改〕

#### T-2 单元格编辑

- 拖动行、列的把手移动行、列。

#### T-4 对齐

- 每列可以左对齐、居中、右对齐：「段落 → 表格」或工具条（T-5）；只改分隔行里这一列的 `:`。

#### T-5 工具条与选择

- 光标在表格里时，表格上方显示工具条：对齐、插入和删除行列、删除表格。

#### T-6 粘贴表格数据

- 从 Excel、网页复制的表格（制表符分隔的文字，或 HTML 表格）粘贴到单元格里，从这一格开始按行列填进去，不够时自动加行、加列。
- 粘贴到正文里时生成新的 Markdown 表格（C-3）。

#### T-7 表格源码〔改〕

- 没改过的表格逐字节不变（通用规则 1）。
- 改过的表格只重写改过的行；新加的行和列按表头行的写法（竖线两边的空格）生成；改了对齐只改分隔行。
- 〔改〕现在改动表格后由表格编辑器整体生成源码。

#### M-6 查看大图

#### M-7 视频与音频

### 2.8 文件与窗口（F）

#### F-1 新建〔改〕

- Ctrl+N：当前窗口是没改过的空白新文档时就用它，否则新开一个窗口（通用规则 5）。
- 新文档的名字是「未命名.md」（随界面语言）。
- 〔改〕现在只有一个窗口，新建会替换当前文档。

#### F-2 新建窗口〔新增〕

- Ctrl+Shift+N 新开一个空白窗口；位置在当前窗口右下错开一点。

#### F-3 打开〔改〕

- Ctrl+O 选文件；可选的扩展名：md、markdown、mdown、mkd、mkdn、mdwn、mdtxt、mdtext、rmd，也可以选纯文本文件。
- 选窗口的规则（拖放、最近文件、快速打开、系统打开文件、本地链接都用它）：这个文件已经在某个窗口里打开时，切到那个窗口；当前窗口是没改过的空白新文档时，在当前窗口打开；否则新开窗口。
- 文件不存在或读不了时提示原因；从最近文件打开失败时，问要不要从列表里去掉。

#### F-4 快速打开〔改〕

- Ctrl+P：输入文件名的一部分，从工作区的 Markdown 文件里找，没有工作区时从最近文件里找；↑ ↓ 选择，回车打开（F-3 的窗口规则），Esc 关闭；最多列 30 个。
- 〔改〕按模糊匹配排序：连续命中、命中词首的靠前，最近打开过的再往前；现在是名字和路径包含关键字就列出。

#### F-5 最近文件

- 「文件 → 打开最近」列出最近的 20 个；「显示最近文件...」打开面板，可以搜索、打开、从列表移除；「清空最近文件」。
- S-4「记录最近文件」关掉时不记录。
- 所有窗口共用一份（1.8 节）。

#### F-6 保存

- Ctrl+S 保存；新文档按 F-7 处理。
- 原子写入：先写临时文件，再替换原文件；保存到一半断电也不会留下半个文件。
- 冲突检测：保存前比对磁盘上的内容和打开时（或上次保存时）的内容，不一样时提示「文件已被其他程序修改」，可以选：覆盖、载入磁盘上的版本、另存为。
- 换行符、BOM、编码按 E-1、F-18。

#### F-7 另存为〔改〕

- Ctrl+Shift+S；默认目录是当前文件所在目录，没有时用工作区目录；新文档的默认文件名取第一个标题，没有标题时为「未命名.md」。
- 另存后这个窗口编辑新文件；最近文件里加上新路径。
- 〔改〕现在新文档的默认文件名固定是 `untitled.md`。

#### F-8 自动保存

- S-3「自动保存」打开时，已经保存过的文档有改动后，按「自动保存间隔」（1、3、5、10 分钟，默认 3）保存。
- S-3「切换文件时自动保存」打开时，在同一窗口里打开别的文件之前先保存。
- 新文档还没有路径，不自动保存，由 F-9 的草稿保护。

#### F-9 草稿恢复〔改〕

- S-3「恢复未保存的草稿」打开时，每个窗口里没保存的内容（新文档，或改了没保存的文档），在停止输入 1 秒后由主进程写进草稿目录（1.8 节）。
- 程序异常退出、系统重启后再打开 Marko 时，按上次的窗口恢复这些文档和改动，并标出「已从草稿恢复」；原文件在这期间被改过时，提示选用草稿还是磁盘上的版本。
- 正常保存，或在未保存确认里选「不保存」之后，删掉对应的草稿。
- 〔改〕现在存在渲染进程的 localStorage 里，每次按键都同步写一遍全文。

#### F-10 未保存确认

- 关闭窗口、退出、在当前窗口打开别的文件、重新载入时，文档有没保存的改动就弹窗：「保存」「不保存」「取消」。
- 退出时有多个窗口没保存，逐个窗口确认，任何一个选「取消」就不退出。

#### F-11 重新载入

- 「文件 → 重新载入」Ctrl+R：从磁盘重新读当前文件；有没保存的改动时先确认（F-10）；光标和滚动位置尽量保留。

#### F-12 外部修改〔新增〕

- 打开的文件被其他程序改了以后：
  - 文档没有没保存的改动：自动重新载入，光标和滚动位置保留，状态栏提示一下；
  - 有没保存的改动：提示「文件已在外部修改」，可以选保留我的改动（之后保存时覆盖）或载入磁盘上的版本。
- 文件被删除或改名后：标题栏标出「已删除」，内容保留，保存时按另存为处理。
- 自己保存引起的变化不算外部修改。

#### F-13 文件操作

- 「文件 → 文件操作」：重命名（只改文件名，扩展名不变）、复制文件路径、在资源管理器（访达）中显示、打开所在文件夹；移到回收站在侧栏的右键菜单里（W-6）。
- 重命名后，窗口跟着编辑新路径，最近文件里的路径跟着改。

#### F-14 系统打开文件〔改〕

- 安装时登记 Markdown 文件关联（F-3 的扩展名）。
- 在资源管理器、访达里双击，或在命令行运行 `marko 文件路径`，都在已经运行的 Marko 里打开（单实例），按 F-3 的规则选窗口；第一次启动时带的文件在第一个窗口里打开。
- macOS 上拖到程序坞图标、「打开方式」走同样的规则。
- 〔改〕现在每次双击都起一个新进程；`main.rs` 只读命令行参数，没有处理 macOS 的 `RunEvent::Opened`。

#### F-15 拖放

- 把 Markdown 文件拖到窗口上：按 F-3 打开；拖文件夹：作为工作区打开（W-1）；把图片、视频、音频拖到编辑区：插入（M-2、M-7）。
- 拖动时显示提示：「松开以打开」「松开以插入」。

#### F-16 关闭与退出〔改〕

- 「文件 → 关闭」Ctrl+W 关闭当前窗口，先按 F-10 确认。
- Windows、Linux 上最后一个窗口关掉就退出；macOS 上关掉最后一个窗口程序还在，点程序坞图标新开一个空白窗口。
- 再次启动时，按 S-3「启动时」恢复上次的窗口、文档和工作区，或者新建空白文档。

#### F-17 窗口标题

- 「● 文件名 - Marko」，有没保存的改动时前面加 ●。
- 〔新增〕macOS 上同时设置系统的「已编辑」标记和文档路径（标题栏可以右键看到路径）。

#### F-18 编码〔新增〕

- 打开时识别编码：UTF-8（含 BOM）、UTF-16、GB18030（含 GBK）、Big5、Shift_JIS 等；识别不出时按 UTF-8 打开，并在状态栏提示。
- 「文件 → 以其他编码重新打开」。
- 保存时沿用打开时的编码；新文档用 UTF-8。

#### F-19 导入〔新增〕

- 「文件 → 导入...」：用 Pandoc 把 Word（docx）、HTML、EPUB、LaTeX、OpenDocument 转成 Markdown，在新窗口里作为新文档打开。
- 文档里的图片先提取到临时目录，保存时按 M-3 复制到文档旁边。
- 没装 Pandoc 时同 O-4 的提示。

## 4 重构计划

2026-11-23 定的目标：换掉桌面壳和编辑器内核，功能对齐 Typora（第 2 章）。

### 4.1 做法

- 一个阶段一个阶段做。每个阶段开始前，把本文件里涉及的部分给用户看，同意后再写代码；做完跑 `npm run check`、`npm test`，按第 2 章的编号逐条核对，汇报后再进下一阶段。
- 新代码放在 `packages/`、`apps/`、`test/`，和旧代码（`src/`、`src-tauri/`、`tests/`、`component-tests/`）并存。旧应用照常能构建、发布；重构期间旧代码只修严重问题，不加功能。阶段 7 切换后删掉旧代码。
- 每个阶段一个分支；小步提交，一个提交只做一件事，提交信息用中文一句话说清做了什么。
- 发现本文件做不到、对不上时停下来，说明问题和建议的改法，用户确认后先改本文件，再继续写代码。
- 〔新增〕的功能放在它所属的阶段里做，不单独排期。

### 4.3 行为规格的格式

`test/behavior/` 下每个功能分类一个文件（如 `E.md`），每条规格一个小节：标题写编号和要验证的事，`before`、`after` 两个代码块写操作前后的 Markdown，中间一行写操作。`‸` 表示光标，`⟦`、`⟧` 表示选区的两端。

````
### E-5 空的列表项上回车，变成正文

```before
- 第一项
- ‸
```

操作：`Enter`

```after
- 第一项

‸
```
````

- 操作写按键（`Enter`、`Shift+Tab`、`Ctrl+B`）、输入的文字（`输入 "# "`）或命令名（`命令 toggleTask`）。
- 测试把 `before` 解析成文档、按操作执行、序列化后和 `after` 逐字节比较，光标和选区也要对上。
- 阶段 0 从现有测试里导出；之后新增、修改的行为先在这里加一条。
