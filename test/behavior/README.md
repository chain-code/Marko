# 行为规格

编辑操作的验收用例：带光标标记的 Markdown → 操作 → 期望的 Markdown。在测试里的位置见 `docs/architecture.md` 1.13 节，格式见下面的「写法」；每条规格的标题以第 2 章的功能编号开头。

## 文件

| 文件 | 内容 |
|---|---|
| `E.md` | 编辑核心（E）：回车、退格、自动转换、选择、删除与移动、自动配对 |
| `B.md` | 块（B） |
| `I.md` | 行内（I） |
| `T.md` | 表格（T） |
| `M.md` | 图片与媒体（M） |
| `D.md` | 公式与图表（D） |
| `C.md` | 剪贴板（C） |

## 写法

- `‸` 是光标；`⟦`、`⟧` 是选区的两端，反向选区写成 `⟧…⟦`；`␍` 是回车符（CRLF 里的 CR）。文本里本来就有这几个字符的，不能写成规格。
- `before`、`after` 代码块的内容是两行围栏之间的全部行，用换行连起来，末尾不另加换行：内容本身以换行结尾时，结束围栏前面多一个空行。围栏比内容里最长的一串反引号多一个，至少三个。
- 操作：
  - 按键写成 `` `Enter` ``、`` `Shift+Tab` ``；
  - 输入写成 `输入 "# "`，引号里是 JSON 字符串；
  - 菜单命令写成 `命令 bold`，名字是编辑器命令的名字（阶段 0 时是旧代码 `EditorCommand` 的；没有对应菜单命令的写的是旧函数的名字，阶段 4 对应到了新命令，见 `packages/editor/test/behavior/`）；
  - 粘贴写成 `粘贴，text = "…"，html = "…"`，粘贴为纯文本（C-4）写成 `粘贴为纯文本，text = "…"`；
  - 影响结果的设置写在后面的括号里：`（Markdown 缩进宽度 4）`、`（语言 "ts"）`（菜单插入代码块的默认语言）、`（默认代码语言 "ts"）`（输入围栏时的默认语言，S-7）、`（源码模式）`（E-11）。
- `<!-- 来源：… -->`：这条是从哪个测试来的。
- `<!-- 旧代码：{…} -->`：阶段 0～6 在旧代码上怎么重放：模块、函数和其余参数（`$state` 是 before 的状态，`$undefined` 表示 undefined，`$text`、`$start`、`$end` 是 before 的文本和选区两端，`expectExtras` 是旧函数返回值里的其他字段）。阶段 7 删掉旧代码以后只是记录，新代码不读它。
- `<!-- 阶段 4 改：… -->`：新编辑器有意和旧代码不同、改过 before / after / 操作的规格，后面写原因（见下面「和旧代码不同的地方」）；旧代码上不重放。
- `<!-- 阶段 4 补：… -->`：阶段 4 补提取的规格。阶段 0 的提取只认参数是状态对象的函数，漏掉了 `tests/editorBlocks.test.ts` 里 Tab、缩进的两个函数（`applyContextualMarkdownTab`、`indentSelection`，参数是「文本, 起点, 终点, …」）；记录器加上了它们（`legacy/record.cjs` 的 `POSITIONAL`），补出 53 条（E-5 的 Tab、Shift+Tab 40 条，B-4 的缩进、反缩进命令 13 条），在旧代码上全部通过。记录器、提取和重放的工具（`legacy/`）阶段 7 随旧代码删除。
- 文件用 LF 换行，保留行尾空格（`.gitattributes` 里设了 `eol=lf`）；编辑器不要自动删行尾空格。

## 在新编辑器上跑

`packages/editor/test/behavior/`（`npm test -w @marko/editor`）：把 before 解析成文档、按 before 的源码偏移放好选区，执行操作，读成源码和 after 比较。

- 光标这一行是要按回车、空格才转换的写法（`---`、```` ``` ````、`$$`、`#` 后面还没有空格……，E-4）时，before 摆成正在输入、还没转换的段落。
- 编辑器里光标、选区进不了块标记（列表符号、任务框、引用的 `>`、标题的 `#`、围栏、表格的竖线、Front Matter 的分隔栏）和行首的缩进：before 的光标在这些地方时落到最近的内容上，按读回来的位置执行。结果相同的规格不改，汇总里记为「before 放进编辑器读出来不一样」（46 条）。
- 选中了分隔线、目录（节点选区）读成这一块的原文；选中了几个单元格（单元格选区，T-5）读成从第一格的内容到最后一格的内容。
- `MARKO_BEHAVIOR_REPORT=<文件>`：不逐条报错，把汇总和失败的规格写进这个文件，同名的 `.json` 是每条的结果；`MARKO_BEHAVIOR_TRACE=<文件>`：随时写下正在跑的是哪一条（卡住时看）。
